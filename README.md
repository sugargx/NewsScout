## 选择运行模式

| 模式 | 身份与数据 | 产品范围 |
| --- | --- | --- |
| 可信本地（legacy） | 本机单用户，数据库与 Copilot 本机登录留在本机；不是公网认证边界 | 完整应用，包括阅读/模型设置 |
| Azure 认证开放预览 | Microsoft账号直接登录，或以邮箱+密码自助注册NewsScout账号；请求权限和PostgreSQL RLS隔离本人数据 | 同一完整应用；阅读/模型管理设置隐藏并拒绝。已验证范围与未完成live流程见运行手册 |
| 旧 Dev Tunnel 匿名只读（已退役） | 历史契约为获得地址即可访问，反馈保存在浏览器 | 保留五个入口的历史代码/操作说明，不作为当前在线站点 |

云端登录不要求试用者提供GitHub token；组织Microsoft账号可能另外需要管理员批准。AAD按tenant/object稳定标识建号，邮箱入口按固定External ID issuer下的subject建号；未知provider、错误issuer和匿名私有请求在建号前401。两个入口默认形成独立账号，不按邮箱或显示名自动合并。显式发布快照和健康检查有匿名例外；身份隔离与应急阻断见 [Azure手册第6.5节](docs/AZURE-PREVIEW.md#65-自助账号身份隔离与访问阻断)。

云端 `/share/:id` 是本人私有编辑器；`/p/:id` 只读取发布时明确选中的不可变快照，可以撤回，不能修改或重新发布同一个快照。可选使用统计默认关闭，当前前端仅发送有限页面类别的 `page_view`；关闭会删除已存的本人可选事件，不删除服务必需的阅读状态或运行日志。本人 JSON 导出最多20 MiB、每用户每小时2次；暂无自助账号删除，请联系维护者。

## 本地启动

要求 Node.js 22+、Rust stable、PostgreSQL 17（手动运行可用 Docker）；Windows 原生 Rust 构建还需 MSVC C++ Build Tools/Windows SDK。新 checkout 尚无依赖时先执行 `npm ci`，启动器不会自动安装 npm 包。

```powershell
git clone https://github.com/sugargx/NewsScout.git
Set-Location NewsScout
npm.cmd ci
```

仓库只分发项目源码、配置模板和文档，不包含维护者数据库、凭据、运行日志、已构建程序或本机留存的第三方参考 PDF。克隆代码不等于复制现有新闻库或获得一个持续在线的公共站点；首次运行需按下文准备运行时并采集来源。

### Windows 一键运行

在项目根目录执行 `npm start`。启动器构建并启动 API、Gateway 和 Web，默认使用独立的本地 PostgreSQL 数据目录；不需要先配置 GitHub OAuth 就能阅读真实 Feed。保持启动器运行，使用 `npm stop` 停止本次本地服务。

- 如果系统 Node/NVM 不可用，可先执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\bootstrap-node.ps1`。它校验官方 SHA-256 后安装项目专用运行时，不修改系统 Node。随后直接执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-local.ps1`；停止时使用同目录的 `stop-local.ps1`。
- 浏览器打开 `http://127.0.0.1:5173`，在“来源”页点击采集，再进入 Radar 阅读。
- 如果缺少本地 PostgreSQL 二进制，显式执行 `npm start -- -BootstrapPostgres` 下载；已有运行时会直接复用。
- `npm start -- -SkipBuild` 跳过 API/Gateway 构建，Web 仍为 Vite 开发服务；需要更新已构建程序时应重新运行不带此参数的命令，不能把该选项当作公开发布。
- `npm start -- -Demo` 只展示带演示标识的样本，不采集新闻、不调用模型，数据不跨重启保存。
- 默认个人数据位于被忽略的 `tmp\postgres-local\data`，PostgreSQL 仅监听 `127.0.0.1:55433`。停止服务不会删除数据；需要保留长期数据时请备份该数据库。
- API、Gateway 和 Web 端口分别是 8080、8787、5173。启动器遇到端口占用会明确失败，不会杀掉其他项目的进程。

### 手动运行各服务

手动调试的逐终端命令见 [运行与发布手册](docs/OPERATIONS.md)。从 `.env.example` 建立本机 `.env` 并配置实际数据库；OAuth App 仅是可选连接方式。API 与 Gateway 必须继承同一份环境和随机内部密钥。手动 Docker 默认使用 5432，一键启动器使用自己的 55433 数据库，不要混淆两份数据。

数据库模式启动时自动执行增量migration。**日常库在9月21日的最终无writer冻结备份及完整隔离恢复后升级至27**；当时20表原指纹保持，14份briefs、3份shares、64个sources、6168个events及Terra/enabled=true/5000设置保留，5173/8080响应正常。这些数量是当次历史快照；9月22日r8升级云端至28、9月24日r11升级至29（只改SQL函数），本地后端均未重启。默认每天Asia/Shanghai **06:00** 调度来源采集，也支持手动刷新；暂停来源不参与自动或全量采集，已保存模型、额度与日程不会因重启重置。

本次24→27保护流程见 [隔离升级预检](docs/OPERATIONS.md#个人库升级前的隔离预检)。现有脚本只接受保留的24版备份，不是当前27库任意后续升级的通用入口；后续升级须另行授权并使用匹配的冻结备份/恢复验证，不篡改迁移记录绕过检查。私有备份不得上传或提交。

### 旧 Dev Tunnel 匿名只读试读

**旧入口已退役。** 本节保留旧5190运行方式作为历史/受控复现说明，不代表当前在线，也不要求重新启动。恢复该入口须维护者另行授权；不将旧只读限制套用到Azure认证完整应用。

先保持个人本地服务运行，再使用独立的 **5190** 只读网关；不要把 5173、8080、8787 或数据库端口直接转发到公网。公开版提供当前共享精选、已保存晨报、新闻雷达、主题图、T1 深读、每周回顾、已收录来源内容与原文入口。收藏、打开记录与不感兴趣仅保存在各自浏览器，不同步设备，不写入站主的阅读记录或推荐偏好；未开放采集、模型调用、账户、来源管理和分享草稿接口。共享精选沿用站主当前精选的选文，但剥离个人状态、推荐分和账户字段，不是为每位访客单独训练的推荐。

访客使用、完整能力矩阵、公开 API 参数和分页边界见 [公开阅读契约](docs/PUBLIC-READER.md)；候选评审、不可变发布、健康检查与排错见 [运行与发布手册](docs/OPERATIONS.md)。

访客可在页面标题旁打开 **兴趣主题**，选择现有的 13 个分类并调整关注程度，保存后用于当前精选及 Radar/主题工作区推荐。兴趣在浏览器保存，选中主题随只读请求参与全体候选排序；不写入站主兴趣，不重跑摘要或改写历史晨报。清空并保存恢复共享推荐。它不替代主题筛选，也不改变深读、周报及“最新优先”的排序。

公开版与个人版复用页面外框、导航、文章呈现、雷达控件与主题工作区。公开阅读导航包括晨间简报、新闻雷达、深度阅读、每周回顾与本浏览器收藏。共用样式本身不证明功能一致；当前支持范围与有意保留的权限差异如下。

- **新闻雷达**：两端均提供“列表 / 主题地图”；原“摘要卡片”视图已在 r10 按最新设计移除，旧 `?view=cards` 地址回落到列表。支持关键词、主题、时间、来源等级、开发构建筛选和推荐/来源时间/来源与热点分排序；不再把公开排序锁定为最新优先。列表每批40条，主题结果每批24组/单篇，可继续加载；同一浏览批次使用固定 `asOf`，手动“应用更新”或应用新兴趣才刷新。公开主题筛选选项来自已载入的文章，不读取站主兴趣；访客兴趣单独影响服务端推荐，不使用本地反馈训练模型。
- **主题关联**：使用同一个 `TopicWorkspace`，包含真实样本量、图谱、匹配文章、筛选后的关联材料和就地阅读。初始展示全部主题的结果，不悄悄选择第一主题；选节点才缩小右侧列表。返回恢复主题、滚动位置和焦点；窄屏在地图与结果间切换，阅读时聚焦文章。
- **T1 深读**：只读 T1 博客目录，可按来源、技术研究/全部博客、过去30天/不限日期筛选；按来源发布时间顺序阅读，分页保持同一时间锚点。大范围队列达到公开分页上限会明确提示，不冒称已读到全部历史。只有主动打开才记录打开状态，可只看尚未打开的文章；取得新原始材料的已知内容版本会重新标为尚未打开。旧浏览器记录保持兼容，不推测之前读过哪个版本。
- **每周回顾**：读取现有滚动七天周报，保留主题分组与顺序；桌面就地阅读，移动端聚焦详情，不开放周报生成或分享草稿。
- **已保存晨报**：在“晨报版本”中选择实际已存档的日期，不补生成缺失日期。历史列表保留当时的标题、摘要、顺序及关联材料；打开文章时明确标注详情为当前已收录版本，不改写历史快照。

安装并登录 Microsoft `devtunnel` CLI 后，一次性创建专用隧道（将 `$tunnelId` 的示例值替换为命令实际返回的完整 ID）：

```powershell
devtunnel create --allow-anonymous
$tunnelId = 'replace-with-the-created-id.region'
devtunnel port create $tunnelId -p 5190 --protocol http
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-public-reader.ps1 -TunnelId $tunnelId
```

启动器只接受恰好配置了 5190 一个端口的隧道，构建并复制独立的生产前端，输出实际 HTTPS 地址。运行信息保存在 `tmp\public-reader-runtime.json`，日志与不可变页面副本在 `tmp\public-reader-runs\<session-id>`。第一次访问可能出现 Dev Tunnel 提醒页，点击 **Continue** 后进入；匿名地址适合邀请试用，但获得地址的其他人也可访问。CLI 语法与访问控制以 Microsoft Dev Tunnels 的命令行参考为准。

```powershell
.\scripts\stop-public-reader.ps1
# 更新代码后用同一个 tunnel-id 重启，重新构建并加载页面与网关
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-public-reader.ps1 -TunnelId $tunnelId
```

停止公开版不会关闭个人版或删除隧道配置；停止个人版会让公开版无法读取新闻。这是本机托管的测试入口，电脑、个人服务和公开启动器都必须保持运行，隧道过期后需重新配置，不是永久云部署。此地址不承载分享工作台或 Azure 的 `/p/:id` 发布快照，不要直接填入分享卡片的公开基础地址设置；旧 Rust 分享只读分支也不是这个网关。

仅重建 `apps\web\dist` 不会替换当前公开 `site`。网关启动时缓存入口 HTML，人工候选也应使用独立副本；不要在旧网关仍运行时覆盖其页面目录。发布记录只证明对应日期的构建，实际在线状态以新鲜运行元数据和入口响应为准。

## UI 规范与独立评审

具体组件契约、断点、文字预算、焦点规则、Critic 输入与发布前后证据要求见 [UI 设计与独立评审](docs/UI-DESIGN.md)。2026-09-20 的改版采用用户确认的 CoDesign 保存版：[原型与工程映射](docs/design/CODESIGN-MAPPING.md) 记录页面、组件、业务差异与实施范围；[补设计 prompt](docs/design/CODESIGN-SUPPLEMENT-PROMPT.md) 用于在同一工作区补齐设置、来源、两套兴趣语义和分享等缺页，不把演示数据或内存状态接进生产。

现有 Fluent UI 继续提供按钮、选择器、抽屉和键盘页签行为；项目自己维护阅读界面的组合与样式，不叠加第二套 Tailwind / Radix / shadcn 运行时。继续使用统一的 `--cp-*` 变量，但浅色已映射到深绿强调、灰绿页面和暖色要点；标题使用编辑式 Georgia / 宋体，正文优先本机中文字体。控件圆角6px、面板8px、对话框10px，普通新闻改为细分隔线列表。深色仍为兼容主题（r10 只修正对比度），完整 CoDesign 深色及管理页方案列入补图范围。

- `ReaderShell` / `ReaderNavigation`：769px起使用176px窄侧栏；768px及以下使用56px顶部栏和五个阅读目的地的250px导航抽屉，不再使用72px窄栏或固定底栏。1024px及以下阅读时从侧栏右侧聚焦阅读器。未知路径显示“找不到这个页面”并提供返回入口，不再是空白页。管理入口与阅读入口分开；旧匿名只读版不渲染管理入口，Azure 完整版保留主题、来源、分享与账号入口，但不开放阅读/模型设置。
- `ReaderStory`：个人版与公开版共用标题、预览、来源日期和下方的辅助操作区。点击标题就地阅读，不重复放置同权重的“查看详情”按钮；列表正文使用可用列宽，不再为侧边操作扣除160px。展开阅读价值、保存中或出错时随内容增高，不覆盖文字或下一条新闻。摘要仍是紧凑预览，打开文章可读完整要点。
- `ReaderButton` / `ReaderControls` / `ReaderProblem`：统一主操作、次操作、轻量操作和危险操作变体；移动端主要按钮与选择器为44px。页签关联实际内容面板，支持方向键；失败区域提供明确的一次重试，不把读取失败当作空数据。
- `RadarControls` / `ReaderRow` / `TopicWorkspace`：两端共用三种雷达视图、筛选控件、紧凑行和图谱-文章工作区；数据通过明确类型的只读/个人适配器接入，不把公开文章伪装成带有个人状态的事件。
- 深读队列在选文前占满可用区域，不预留巨大的空详情框；1280px起使用312px队列与阅读区，较窄宽度聚焦文章，并保留返回、当前位置和前后篇控制。主题工作区在窄屏提供地图/结果切换，文章窗口复用焦点约束和背景隔离，不影响浏览器收藏的独立性。

```powershell
# 针对宽屏文字布局、展开阅读价值以及鼠标/键盘选择器焦点
npm run ui:review -- --scope width-focus --output tmp\ui-reviews\my-width-review
```

命令使用已有 Playwright，覆盖1280/1024/768/390宽度及代表性深色界面，保存截图和 `review.json`。包括雷达两种视图（列表、主题地图）、主题筛选与阅读、队列、详情、原文（当前队列中可用时）、空收藏，以及明确标记为浏览器模拟的加载/失败状态；模拟不修改服务器。目标必须是声明只读的本地公开网关或 HTTPS Dev Tunnel，阻止个人 API 与非读取请求。输出必须是 `tmp\ui-reviews` 下的新目录，不覆盖旧证据；构建后的候选网关也可作为目标，不必提前替换公开站点。`editorial-reader.spec.ts` 的 Radar parity 用例另外生成相同内容的个人/公开对照截图；截图脚本本身不调用 AI，也不自动授予验收结论。

`width-focus` 范围单独覆盖1440/1920/390宽度的明暗主题，记录实际文字宽度和选择器焦点。Fluent 输入框、选择器使用组件自己的焦点行为，公开页不再额外叠加外轮廓；选择器采用与输入框一致的2px底线，不随10px圆角被放大。普通链接和按钮仍保留键盘焦点。

## 日常使用

以下阅读与工作台能力由可信本地和已开放的Azure认证预览共用。Microsoft真实登录/读取、双provider控制面和后端身份隔离已验证；完整真人邮箱注册及其余私有编辑、偏好写入、发布撤回、导出等仍有live覆盖限制，不能把实现契约当作全部验收。账号数据分别写入本机或本人云端作用域，未迁移本地历史到云端；已退役Dev Tunnel的浏览器反馈是另一套历史契约。

- **Radar**：默认仍为近72小时的推荐与“列表”，可显式选择“最近24小时”切换到24小时/最新，或“值得阅读”切回72小时/推荐，并保留搜索、主题等条件。支持“列表”和“主题地图”；搜索、主题、来源等级在主控件区，时间范围/排序/开发构建在“更多筛选 · 时间与排序”。只有收藏和不感兴趣两个主动反馈入口，均可撤销；旧稍后读记录自动归入收藏。
- **文章阅读**：桌面阅读器固定在视口右侧，列表和状态保留；1024px及以下聚焦文章并限制背景交互。阅读器最大720px、正文最大680px，关闭后恢复原列表位置与焦点。可展开“阅读价值”查看摘要生成时对文章内容的现有解读；未生成时不编造理由，也不把内部规则版本、基础分或分类日志当作阅读说明。明确区分来源提供的发布/更新时间与收录时间；部分 Atom 来源只提供更新时间，不保证是首次发布。未知来源时间不由收录时间冒充，只有日期的来源不伪造时分秒。Feed 摘录不是阅读全文后的摘要。
- **加载与等待**：列表和阅读队列使用对应布局的骨架，不在首批数据返回前显示“0 篇”。详情等待期间保留已知标题与摘要，并可关闭或切换文章；失败时提供重试，不把读取失败显示成空列表。骨架尊重减少动态效果设置。
- **简报**：每天北京时间6点固定为一期，下一期之前直接返回保存的快照；6点后当期仍在生成时（最多3小时）先显示上一期并标明，后台摘要完成、窗口切换和网络重连不会替换正在阅读的文章。选文先排除不感兴趣、未通过精选资格、代码仓库、只有哈希编号的构建、聚合平台的二次摘要和超过7天的内容；最近24小时的内容组成一个严格按分排序的主列表，事件重要性权重最高，其次是信息价值、兴趣、新鲜度、质量与偏好，已打开或已看过的内容轻度降权。同一发布者最多2条，社区讨论、索引页各2条，播客3条，同一主题5条；96小时内同一模型版本的第三方报道只留一篇，官方发布方自己的公告不受此限。较早内容须重要性≥60且价值≥70才进入“值得补读”，最多3条。默认上限20条，可设5–30条，不以普通求助或宣传短讯凑数。默认允许最近采集健康的观察来源，可在设置中关闭；采集健康不等于来源可信。GitHub 发现查询不进入简报。
- **更新与存档**：“应用更新”只读取已有内容与反馈；来源管理中的采集操作才访问来源并反馈新增、更新及失败情况。没有更新计数接口时不显示虚构的“4条新内容”。每日晨间版与历史简报是不可改写的快照，“重新读取历史版”不会变出新文章。个人不感兴趣反馈可以隐藏快照中的展示项，但不删除或改写原始存档。
- **来源**：按 T1 / T1.5 / T2 筛选，查看来源/领域覆盖及尚缺入口，搜索来源、检查健康、暂停/启用、逐源或全部刷新，并添加受支持的公开 HTTPS Feed/API。Azure 的公共来源种子配合本人覆盖设置，自定义来源及其材料按账号隔离；“私有来源”不是允许抓取私网或绕过原站登录。云端采集返回异步任务，每批最多100个来源、每用户每小时6次提交且最多一个活动任务，同一来源有全局2分钟提交间隔；没有取消接口。观察中的来源成功采集后，可明确确认其参与简报；这不会提升信源等级或赋予官方身份。GitHub 发现查询不可整体确认为可信来源。
- **兴趣与反馈**：显式兴趣参与个人推荐，不冒充全局热度。收藏提高相近主题的偏好，不感兴趣降低相近主题的偏好并隐藏该条；影响有界，单条反馈不会封禁整个机构或领域。收藏与不感兴趣记录保存在所属模式的个人数据库状态中，反复点击不会累加虚假的反馈次数。

### 推荐与重复展示

**集中发布分组**：对于原始 GitHub Release 中可确认的同一官方仓库、组件类型、版本及匹配的目标标签，在最多24小时的来源时间跨度内，把同批次的不同组件收为一组。新分组标记为 `release-family-v2`。插件 / 扩展 / 适配器 / 集成保留各自家族；SDK、CLI 与具名 SDK Provider 可以构成客户端家族，但必须有同仓库的明确共同改动引用，不能只凭品牌、相近日期或相似文案合并。

版本号属于各组件，不要求跨组件相同。Node CLI 与 Node SDK 是两个组件；Node / TypeScript SDK 则作为同一组件的名称变体，不能把其不同版本塞入同一组。标签接受与产品/组件匹配的语言别名、CLI 标签和默认 SDK 版本标签；具名 SDK Provider 的发布标签必须对应其宿主。不同仓库 / fork、非官方材料、只有日期而没有精确时间、无法确认的产品或标签，以及互不相交的明确改动仍分开。既有插件材料没有改动引用时仍只在原家族与时间边界内处理，不用无引用条目连接两个冲突批次。

包发布另有独立家族：标题严格对应 `包名==版本`，核心包名须与仓库名一致并匹配裸版本标签；子组件须为 `仓库名-组件` 并匹配 `组件==版本` 标签。只将标签中的 `%3D` 解码为等号一次，不猜测其他编码或标点别名，也不与既有客户端/插件家族混组。仍须官方材料、精确时间、同仓库共同改动及24小时总跨度；同一组件的连续版本不能并入一组。例如 `langgraph==1.2.12` 与 `langgraph-sdk==0.4.5` 的明确共同改动可形成“langgraph 同批更新：核心包 1.2.12 / SDK 0.4.5”，但不是同一篇新闻的多方互证。

分组先按来源时间确定批次，之后才选择排序中的主条目。同一候选集合和时间锚点下，推荐分、访客兴趣或排序变化不会让一个跨组组件在两组间来回移动。组内共同改动保持交集：OpenClaw 同时涉及安装统计和遥测，不代表 OpenCode 与 Pi Agent 的改动也相同。

例如2026年9月18日这批 Mem0 发布，完整材料中 OpenCode / OpenClaw 展示为“Mem0 插件更新：安装统计”，Pi Agent / DeepSeek 为“Mem0 插件更新：遥测”；Python / Node 的 SDK、CLI 与 Vercel AI SDK Provider 共享客户端身份标识改动，可展示为“Mem0 客户端更新：调用来源标识”。标题只使用所有成员原始说明都支持的有限主题线索；缺少线索时列出具体组件名称，不编造综合摘要，也不调用模型生成组标题。

卡片保留每个目标、独立版本和原有摘要的首条要点，展开后仍是每篇原有摘要、时间与出处；首篇内容不会冒充所有组件的综合结论。同一发布者拆成多个条目不会变成多方报道或获得额外热度。收藏、不感兴趣和单篇分享仍针对具体组件，隐藏一项不隐藏其他成员。

当前精选在筛选、分页和名额计算前收拢。旧晨间快照只在读取时对已捕获的独立发布条目收拢展示，不改写存储 JSON、不加入后来收录的材料、不改变原始正文或版本。已保存的 `release-family-v1` / `v2` 分组保留其原有标题与成员，不用新规则重命名旧组。历史弱名称关联不再解释为同一事件；已捕获的成员必须保留，按历史版中的独立文章阅读。

Radar 与新生成的当前简报仅根据**同一个精确事件引用**或上述发行家族收拢材料。精确引用目前包括直接指向同一 GitHub 发行标签、PR、Issue 或 arXiv 条目的证据链接，并要求来源时间跨度不超过七日。每篇的事件 ID、证据 ID、时间、摘要、收藏与曝光记录仍独立。收藏库仍逐条展示；Radar 在原有等级、来源、主题、时间、搜索和状态筛选之后收拢，再按组分页，包内不会偷渡不满足筛选的条目。

相同品牌名、产品名、裸仓库地址或正文中的偶然链接不构成同一事件证明。因此金融服务和抗菌分子研究不会因为都提到 ChatGPT 而合并；同名的 Grok Bot 社区项目也不会被冒充为媒体报道的互证。保留原始拼写，不再把 ChatGPT、iPhone 拆成残缺名称。缺少明确事件引用时可能漏关联；主题探索仍可用于寻找更宽泛的相关内容，但不宣称完整语义聚类。

仅含哈希或明确 handoff/runtime/build/nightly 构建标签的发布默认不进入晨报和雷达；雷达的“包含开发构建”对应 `includeEngineering=true`，在筛选与分页之前生效。正常语义版本发布不因此排除，已收藏的构建和直接文章链接仍可访问，原始记录与标签不删除。

覆盖包分别显示编辑来源数、官方来源数、编辑 / 官方材料份数和社区参考份数。新编辑策略将独立报道覆盖限制在推荐权重的5%以内，分组不再额外叠加热度；同一发布者拆成多个条目和社区仓库元数据不被视为独立互证。旧版记录仍兼容原有的有界覆盖字段，但不改写旧快照。主条目的新闻时间和摘要不被其他成员替换；包内是各篇独立摘要，而不是新模型生成的“综合结论”。本次阅读仍固定顺序，分享沿用本次可见主条目选择。

**编辑策略与个人排序**：先区分新闻、发布、研究、分析、教程、讨论、普通求助、宣传和仓库元数据，再判断是否有资格成为精选。内容价值是版本化、可解释的规则判断，不是模型质量认证，也不表示文章已经被独立核验。官方身份不自动使一篇营销短讯重要，社区身份也不自动排除有实质内容的实践。

推荐按内容价值30%、来源与证据质量25%、显式兴趣20%、时效性15%、主动反馈5%、独立报道覆盖5%组合，再应用有界的重复展示调整。不同内容类型采用不同的时效衰减，后续转载不重置同一事件的新鲜度；来源时间仍不冒充已核实的事件发生时间。最终选文还受来源多样性和版块名额约束，因此不是简单截取一个分数榜的前20名。

这是可回放的首版编辑策略，而不是已经训练完成的个性化模型或经过用户实验确认的最优权重。原有“来源与热点分”是另一个非个人排序口径，不应被解释为个人推荐分。文章主题、推荐标签和主题探索使用统一的文章分类；来源配置中的主题仅是来源提示，不代表该来源每篇文章的主题。硬件显存与 Agent 记忆、内容主题与播客这种内容形态分别处理。

主动反馈集合在单次推荐查询内显式复用，避免来源增多后为每个候选反复扫描整个目录；不改变上述权重、反馈含义或选文结果，也不以过期缓存掩盖数据服务超时。

历史分组先用同一套精确事件引用规则找出可能合并的条目，再加载其覆盖材料；普通博客和播客保留单条位置，不为一页结果解码整个历史目录的摘录。仍然先筛选、分组，再分页，不通过提前截断候选来加速。

“刚刚 / 登顶”等即时或榜单式标题不证明新闻重要或刚刚发生。只有短摘录的标题型材料与包含真实原文、方法和结果的材料分别判断；材料不足不等于认定新闻失实。缺少事件级证据时，仍保留来源日期而不伪造旧闻关联。

仓库元数据按低内容价值处理并退出精选：项目新建、推送或元数据变化不等同于新闻发布，不能因为时间新就占满晨报。雷达仍可用于发现这些候选，明确区分元数据与实质材料。原始链接本身不构成“已获取官方证据”，须有来自真实发布者的直接材料。

条目至少一半进入可见区域并停留1.5秒才记录曝光；打开详情记录浏览。这些行为只用于降低重复展示，不视作“喜欢”。同日同内容版本曝光幂等；证据版本更新后重新获得新内容展示机会。当前列表以进入页面时的 `asOf` 固定曝光截止时间，阅读时不会因刚产生的曝光立即跳动，“应用更新”再应用最新记录并报告实际新增、内容更新或排序变化。以前没有记录的浏览无法追溯，不能声称知道用户昨天看过的所有文章。

不感兴趣默认立即隐藏，并可撤销；可选原因区分主题、来源、旧闻和内容价值。旧闻等原因不应被当作对整个主题的否定，旧 Dev Tunnel 匿名试读的反馈仍只保存在访客自己的浏览器，不写入站主偏好。打开不等于读完，也不要求用户再维护一个手动已读状态。

主题地图基于最多100条匹配新闻中的关键词分类共现：节点大小对应文章数，连线粗细对应共现数。地图聚焦所选主题及其直接共现邻居，其他主题提供单独切换入口；没有共现的主题不会生成虚构连线。支持缩放、放大后拖动与还原视图。桌面右侧在可分页文章列表和阅读面板之间切换，返回后保留主题、位置和焦点，不把长文章追加到列表下方；1024px及以下地图与结果上下堆叠，选择主题可定位到结果，选文后聚焦阅读。边表示同篇共现，不表示因果、事实核验或完整语义知识图谱。

来源页分为“已接入来源”“关注名单”“覆盖与管理”。等级、关键词、适配器与采集状态共同筛选已接入来源，结果紧接筛选器显示；筛选条件保存在网址中，刷新和切换页签不会丢失。尚待确认或授权的关注项不冒充已接入来源，也不被虚构分配 T1 / T2 等级。

关注名单另外支持**平台、接入状态与关键词**筛选，条件与订阅来源的 T1 / T2 筛选独立保存。2026-09-10 收录的“yikai 的信源整理”包含86个明确对象，另记录知乎、即刻两个未指定账号的平台意向；保留文档块与原始链接。已核实的原始 Feed 关联真实订阅；官网 / 节目订阅不代表覆盖其全部社交、视频或历史内容。X、微博、B站等尚未接通的入口和失效链接明确列出缺口，资料目录仅作参考，不作为聚合新闻采集。没有代替用户执行平台关注。

版本化目录位于 `services\api\src\source-directory-2026-09-10.json`。数据库启动在增量 migration 后事务性导入：按原始 endpoint 复用订阅，保留既有名称、暂停状态、健康记录与关注备注，新订阅进入观察状态。`source_directory_imports` 记录完成标记与规范化内容哈希；重启不重复导入，已应用的目录不得原地改写，后续变更使用新版本。登记成功不等于抓取成功：关注项显示首次采集、实际错误或暂停状态，不能用登记数量冒充接通数量。

普通 Feed / API 保持4 MiB响应上限；`podcast_rss` 为容纳发布方包含多年节目说明的原始 RSS，采用独立的16 MiB上限，HTTP长度、流式读取与解析阶段都执行相同边界。所有 Feed 仍按来源时间取最多200条，不下载音频，不承诺完整节目历史；更大响应会明确报错，而不是无界抓取。

原文第109块明确将“跨国串门儿计划”描述为 AI 翻译、克隆英文播客。它保留为参考关注项，不进入原始新闻采集；首次目录登记留下的订阅记录暂停保留供审计。该纠正由独立、带完成标记的一次性来源策略应用，不改写已应用目录文件，也不反复覆盖后续用户操作。

### 深读、周报与每日分享图

- `/reading` 默认筛选近30天的 T1 技术与研究材料，按原始栏目、RSS分类及明确技术标题规则识别，不把所有公司新闻都标成深度技术。展示真实首篇和“接下来”队列，用户主动开始后才打开文章；支持全部博客/全部已收录日期、逐源筛选、顺序阅读与“已打开”状态。打开不等于读完，识别不等于人工质量认证，也不承诺完整历史覆盖。
- `/weekly` 按主题组织过去7天、原始来源且已完成摘要的有价值材料，最多20篇；先选择一个真实主题或“全部主题”，前后篇跟随该范围。不因用户已经浏览而漏掉值得回顾的内容，不沿用晨报的曝光去重排序，也不把当天热门求助复制成周报。不额外调用模型生成整份周报；历史日期仍是基于当前已收录材料的回顾，不是不可改写的历史周报存档。
- `/share`（导航“今日分享”，今日精选页的“生成今日分享图”）直接使用当期今日精选，不另选新闻，也不再调用模型。默认取前10条、最多15条；每条是标题、取自当期摘要要点的几句话概述，紧跟原文链接。排序可选“AI 相关优先”（按主题和关键词分为AI相关与其他两组，组内保持精选顺序）或“精选顺序”（与今日精选页一致），选择保存在本浏览器。“值得补读”的较早内容默认不选入，勾选后标注“补读”和发布日期，并始终排在最后。
- 可以逐条勾选、恢复默认、复制文字版，或一键下载1080px宽的PNG长图；支持系统分享的浏览器另有“分享图片”。图片在浏览器本地绘制，不上传，也不创建公开链接；不足10条时不凑数，超过单图高度时提示减少条目。页面打开期间若新一期保存完成，只提示“换成新版”，不替换正在挑选的内容；旧期或仍在生成时，标题写明日期而不是“今日”。
- 旧的图文草稿工作台及文章、周报上的“制作分享卡片”入口已移除，`/shares` 与 `/share/:id` 跳转到 `/share`。此前已公开的 `/p/:id` 链接仍可访问，可在 `/share` 底部“已公开的分享链接（旧版）”打开或撤回；撤回后原链接失效，但不能收回他人已下载的副本。

## GitHub Copilot 连接

下面的“本机登录”和Windows Credential Manager仅用于可信本地。**Azure使用一次性 Device Flow 授权的 GitHub App user token bundle，不读本机keyring、不注入 PAT，也不回退本机登录。** bundle 保存在 Key Vault `copilot-github-oauth-bundle`：8小时 access token 在到期前自动刷新，每次同时轮换6个月 refresh token。预期GitHub数字账号ID还作为独立的非秘密部署设置固定；Gateway首次使用及每代轮换后都会调用 `/user` 核对，不信任可写bundle自报的账号。GitHub返回新token对后旧refresh token已失效，因此Gateway先保留并尝试持久化新一代，再做账号核验；Key Vault写入或账号核验暂时失败时不会重用旧refresh token，而是在内存中保留新一代并持续重试。健康状态只有在账号和Key Vault写回都实际验证后才ready。Microsoft读者身份与服务账号独立，试用者不能修改账号、凭据、模型或额度。

默认直接复用本机已登录的 GitHub/Copilot 账户，**不需要创建 OAuth App、复制 token 或提供 API key**。GitHub Copilot SDK 通过其受支持的本机登录机制读取现有 Copilot 登录或 GitHub CLI 登录；未登录时可在终端执行 `gh auth login`，然后在“模型与账户”页点击“连接本机 GitHub/Copilot”。普通 GitHub 登录不保证 Copilot 模型资格，页面展示的是实际探测到的账户和可用模型。

数据库模式启动会恢复所选本机登录；自动摘要启用且有可用账户时，后台会按设置处理队列并消耗该账户的 Copilot 用量。连接方式保存在 PostgreSQL 的 `app_settings` 中，不含凭据；断开后重启仍保持断开。更换本机账号后请重新探测。断开本机连接只停止 ScoutNews 的 SDK client，不退出 GitHub/Copilot、不撤销全局 token，也不删除全局凭据。运行时环境中的 `GH_TOKEN`、`GITHUB_TOKEN` 和旧 `COPILOT_GITHUB_TOKEN` 不参与此本机账户通道；Azure host 检测到旧 PAT 注入会拒绝启动。

默认摘要模型改为 `gpt-5.6-terra`。后台摘要和手动摘要的默认选择统一来自设置页保存的模型，不再自动调用 GPT-6。只有该精确 ID 在账户实际可用列表中才会选中；不可用时队列暂停，不替换成其他模型，也不提供自动选模的 `auto` 项。账户策略禁用的模型不列为可用模型。之前已经生成的摘要保留其真实模型标记，不伪装成 Terra 生成。

摘要格式v3使用自适应中文要点：短消息1–2点，中等材料3–4点，丰富的正文或节目说明通常4–8点，不限定五句或填充长度。安全上限12点 / 要点2400字，全部摘要和独立说明合计3600字。阅读界面不显示模型/推理配置或“材料范围”警告面板；采集边界仍保留在结构化数据中，“原文提及的局限”只展示原文明示的限制。旧快照仅作展示转换、不改写原始文本。

新的摘要可同时提供独立的中文阅读标题；原始标题保留，用于原文归因、身份和事件关联。没有中文阅读标题的旧记录继续显示原题，不从摘录截取一句话冒充完整标题，也不为标题补齐全量重跑历史摘要。展示标题和摘要的更新不把旧材料伪装成新发布，不改写已保存简报。

模型仍默认 `gpt-5.6-terra`，支持推理强度时明确配置 `low` 并核对真实能力列表；不支持时不偷偷改用更重推理。格式升级仅自动重排近30天、已收藏及尚未生成摘要的材料；旧摘要保持可读，替换成功后才更新。格式升级不重置事件内容版本，因此不会伪装成新新闻；晨报仍接受可用的v2摘要，不等所有历史升级完成。

如仍需 OAuth App，可填写 `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`，并将 callback 设置为 `http://127.0.0.1:8080/api/v1/auth/github/callback`，与 `.env` 一致。配置后设置页才显示 OAuth 入口。此替代通道的 token 保存在 Windows Credential Manager（service=`ScoutNews`，account=`github-copilot-token`）；断开 OAuth 会删除应用自己的凭据并尝试撤销应用 token，与本机登录通道互不混用。

手动启动时生成随机 `COPILOT_GATEWAY_SHARED_SECRET`，Rust API 与 Gateway 使用同一值；一键启动时如未设置，则为本轮服务生成随机内部密钥。摘要在隔离的工作目录运行，使用现有 CLI home 的仅是本机认证及 SDK 自身运行数据；清理只删除本次创建的 ScoutNews UUID 会话，绝不清理用户的 CLI home 或其他会话。

### 自动摘要与历史补生成

新内容入库或证据变化时，在同一数据库事务中进入持久化摘要队列；升级时已有的原始摘录也进入队列，优先处理近期事件，并按当日各主题已完成量兼顾覆盖，避免一种来源占满预算。默认启用自动处理，每次只运行一个模型请求。任务拥有版本约束、五分钟租约和有限重试，重启后可回收中断的任务；不会因重复采集重复创建任务，也不覆盖处理期间已发生变化的证据。

本地设置页可暂停/恢复、选择模型、调整额度和查看队列；云端管理设置仅由维护者管理。新库初始上限 **20次**，可明确设为 **1–5000**，运行时使用PostgreSQL已保存值，重启不重置。当前云端聚合记录应用限额已由20经200调整至5000；本地原有5000则保持未变，二者不是云端新库默认。自动/手动共享滚动24小时全站预算，失败也计入；达到上限保留队列，不切换账户或模型。初始20次尝试的验证快照不是当前限额，最新时点见 [Azure手册第1节](docs/AZURE-PREVIEW.md#1-带日期的-rollout-状态)。更高应用限额不等于上游免费额度或费用保证。

私有 API 仍可按需生成摘要，与后台任务共享单请求锁和用量预算；后台正在生成时应等待当前任务结束。阅读面板的“重新读取”不生成摘要。尚未处理或失败的事件继续提供明确标注的原始摘录，不能当作 AI 摘要。

摘要只使用该事件的标题和已持久化的来源材料，不访问本机文件、不调用工具、不自行抓取原文。来源材料的共享输入预算为16000字符，按证据分配而非让第一篇耗尽；可使用保留的 RSS 正文、节目说明及合规取得的原站文章文本。必须返回可解析结构和已提供的证据 ID，否则保留原有内容并记录失败。没有全文时不会声称读过全文。模型输出不是事实保证，阅读时仍应核对原文。Azure OpenAI 在本版仅保留配置位置，尚未实现调用。

### 就地阅读与来源内容

晨报、雷达、收藏、T1 队列和周报共用就地阅读：桌面右侧展开，移动端聚焦阅读，关闭或返回时恢复列表位置。只有明确打开文章才显示“已打开”；被动曝光不冒充阅读，展开一个分组也不会把所有成员标成已打开。阅读时不自动重排列表，“重新读取”只获取已有内容，不触发采集或模型请求。从保存晨报打开的是文章当前版本，保存版的选文和摘要不随之改写。

详细文章的 `Evidence.readingContext` 按原始证据分别保存，列表不携带大段正文。晨报先显示最多两条简短要点，点击文章标题再展示完整摘要；已有较丰富的来源内容时可切换查看并展开已收录文本，不冒称全文。晨报列表不放逐条分享按钮，保留整版和详情分享。帖子优先显示实际取得的正文；播客显示节目说明、真实章节/时长以及发布者提供的文字稿链接。文字稿链接不代表已经读取文字稿，更不代表听过音频。旧 Dev Tunnel 匿名版只读取已保存的材料，阅读记录和反馈仍隔离保存在各自浏览器；Azure 登录用户的这些状态保存在本人云端账号下。

Stratechery 的明确付费订阅边界会截掉其后的登录、价格和节目目录，保留可公开读取的导语并标为部分内容；不足600字的此类预览不进入新晨报和周报。订阅目录不贡献主题或内容价值，也不进入后续模型输入。普通“subscribe”字样不会触发这一规则，完整分析不因发布者身份被排除。旧材料在读取时清理，不批量改写已存原始材料、摘要或历史版本，也不绕过付费访问。

私有 `POST /api/v1/events/{id}/reading-context` 可针对已收录文章补充最多三个原始博客或 Reddit 帖子来源，返回实际成功、失败和更新数；遵守来源退避、robots 和正文提取边界。材料变化才更新相关摘要输入，获取状态、时间和评论票数变化不触发重算。Feed 提取器升级后按源重读一次，保持内容幂等；节目说明中的广告段落不会导致后续真实章节被截掉。打开文章和公开试读均不会调用此操作。

Reddit 评论补充使用原站单帖 Atom 的有界解析与策略检查，只接受该帖的真实 `t1_` 评论，最多保留十条、每条4000字符。Atom 没有票数，`score` 保存为 `null`；请求 `sort=top` 不等于验证过高赞排名。2026-09-11 的实际尝试中，帖子列表 RSS 可读取，但评论 RSS 遇到429且 robots 不允许自动访问；没有取得或填入真实评论，授权 API 也尚未配置。当前接口会明确返回失败并退避，不用浏览器或镜像绕过该限制。已有帖子正文仍可阅读。

已加入原始博客的浏览器读取方式。本地启动器默认仅为 `openai.com,www.openai.com` 启用，使用已安装的 Edge；可通过 `SCOUTNEWS_BROWSER_ARTICLE_HOSTS` 设置精确主机名单，空值关闭。普通 RSS 仍负责发现文章，正文补全按原站选择 HTTP 或浏览器，每个来源每轮最多三篇；私有补全接口也采用同一方式。浏览器只允许登记原文及同源只读请求，固定已校验的公网 DNS 地址，禁止跨文章跳转、私网、下载和 WebSocket，不使用现有浏览器账户或规避验证。来源返回访问拒绝或验证页时明确失败，不将其当成文章。

浏览器正文与 RSS 保持同一内容身份，保存读取方式和真实获取时间；仅正文等实质材料变化才重新排队摘要。已成功收录的正文不会因随后一次读取失败而被短 Feed 摘录覆盖。HTTP 正文和浏览器分别记录退避，来源级的服务端退避仍共同遵守。浏览器结果有时间、长度和文章标题校验，不接受模型生成的“原文”。手动启动 API 时还需设置 `SCOUTNEWS_BROWSER_NODE`、`SCOUTNEWS_BROWSER_CAPTURE_SCRIPT` 的绝对路径；一键启动器自动提供。

### 每日晨读

每天06:00（Asia/Shanghai）持久化领取一次任务，采集后继续异步摘要，不等待整个历史积压清空。当前新闻就绪目标为12条或用户设置的较小上限；观察来源开启时，其健康来源的当期待处理新闻也纳入就绪判断。当期不足时，须等当期任务结束再用近几日内容补充，不会拿已经处理的旧新闻抢先固化晨报。合格候选全部处理完仍不足目标时如实保存较少条目。超过一小时仍不足时显示未就绪状态，而不是固化空报。上游限流、采集与摘要失败会明确显示，手动刷新不会绕过上游退避。

**可信本地模式的电脑和应用必须运行才能采集；Azure 则依赖其应用副本及数据库持续可用。** 开放预览部署固定一个常驻副本，不代表生产可用性保证。错过06:00会在恢复运行后补采，并显示实际开始时间，不伪装成准点运行。今天的时间点已过时才首次启用或修改日程，首次计划从明天生效。本地晨间任务重启后恢复中断进度，已成功采集的来源不会在同一日任务中再次请求。已有当天快照不会被自动任务覆盖；后续新闻仍可在 Radar 查看。云端手动采集任务若租约过期会明确失败，不能把“支持重启”解释成每个任务必然自动续跑。

- Anthropic News 按索引中的有日期文章卡片识别公告，支持 `/news/文章` 及官网根路径公告，不将产品导航、站外链接或脚本数据当作新闻。已识别卡片缺失标题/日期、地址不符或超过200条时整次采集报错，不再用其他旧文章的解析成功掩盖部分漏项；这仍不代表完整历史或分页覆盖。保留仅日期与精确时间的区别，补采不改变原始发布日期，也不会用收录时间把旧日期材料塞进24小时筛选。
- 元数据采集保持保守：arXiv 最低 12 小时，GitHub Search 最低 24 小时，仓库元数据最低 6 小时，HF 最低 1 小时，Anthropic 最低 3 小时；上游要求的退避不会被“手动刷新”绕过。首次列表有明确条目上限，不宣称全量历史或完整平台覆盖。
- 处理链路：持久化自动摘要队列、Terra 默认模型、历史补生成、共享限额、有限重试与状态展示；已完成摘要且来源符合当前设置的事件才能进入新简报。原有收藏、兼容阅读字段、内容身份和历史快照保留。
- 仍有缺口：完整个人Builder名单与授权端点、X官方API、微信公众号逐源适配、完整分页/历史回扫、Azure第二个真实账号及私有偏好/编辑/发布/撤销/导出的live用户流程、生产运行保障、趋势时间序列、Podcast转写、语义聚类与完整事件关系图、合并/拆分及连续14天质量验收。已验证的单账号OAuth/读取、维护通道采集与摘要不扩大为这些范围；来源页不以虚假频道凑覆盖。
- 当前 migration 已含可扩展 Source Registry；后续增加来源应新增数据或 adapter，而不是增加固定“渠道”枚举。
- 可信本地 API/Gateway 仍不是公网权限边界，不得直接转发。旧本地隧道只允许5190；Azure 则只把 Node 3000 交给平台 HTTPS ingress，Rust8080与Copilot8787始终仅监听容器 loopback。Azure 私有 API 校验可信代理密钥、平台 principal，以及写请求的精确 Origin 和每用户 CSRF，再通过事务内 `SET LOCAL ROLE` / RLS 访问本人数据；不能用开放本地端口替代这些边界。

Windows 原生构建 Rust 需要完整 MSVC C++ Build Tools 与 Windows SDK。若 `link.exe` 报缺少 `msvcrt.lib`，应修复 Visual Studio Build Tools 安装并从 Developer PowerShell 启动；不建议把本机 SDK 绝对路径写进项目配置。

## 真实端到端测试

先按 [测试与证据指南](docs/TESTING.md) 选择范围，区分页面替身、网关契约、隔离真实语料和实际隧道；纯文档变更无需运行采集或模型任务。

运行 `npm run test:e2e:live`。首次执行会下载官方 PostgreSQL 17 二进制到被忽略的 `tmp/`，建立独立测试数据库，使用与日常服务不同的端口启动 API、Gateway 和 Web，然后由 Playwright：

- 直接访问 OpenAI News、Google DeepMind、Microsoft Agent Framework Release Atom 和 Rust Blog 的公开 Feed；
- 要求全部已登记 Feed 本轮采集成功，并验证真实条目进入 PostgreSQL；
- 从 Radar 打开动态采集到的事件，核验官方证据和原文 HTTPS 链接；
- 收藏事件、刷新页面，并验证 PostgreSQL 状态仍存在；
- 验证绕过 Rust API 直接访问 Copilot Gateway 时会被内部密钥保护拒绝。
- 验证重复采集、评分与文本规范化、阅读状态持久化、简报快照和历史、来源管理及失败输入处理。

原始 Feed 集成测试访问真实发布者；交互、字段边界与编辑策略回归另外使用明确标识的受控数据和页面请求替身，不把测试样本当作真实采集成果。隔离启动器设置 `SCOUTNEWS_DISABLE_COPILOT_RESTORE=true`，禁止自动恢复授权，也禁止 API/Gateway 访问本机登录；不会读取用户的 Copilot 凭据或实际消费模型额度。覆盖精确默认模型选择、本机登录隔离和断开偏好持久化。

测试依赖公网和来源站点，因此来源不可用会作为真实失败报告，而不会切换到 mock。测试数据库与 `tmp\postgres-local\data` 中的日常数据隔离，不清空日常数据库，不停止不属于本次运行的服务。

`scripts\test-e2e-live.ps1 -SkipBuild -ApiExecutable <已构建的候选程序>` 可以验证独立构建的 API，避免覆盖 Windows 上仍在运行的日常程序。`-TestPattern` 筛选测试名称。可额外提供 `-DatabaseBackup <本地备份>`，启动器只会把它恢复到本次新建的 `scoutnews_e2e_<UUID>` 隔离数据库，结束后清理该数据库；不会恢复或修改日常数据库。真实语料评估用于检查选文、历史快照与页面响应时间，不能仅凭小型合成样本通过就发布新策略。
