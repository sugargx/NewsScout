# UI 设计与独立评审

适用版本：0.2 阅读端改版，r10 按 CoDesign 最终保存版 1:1 重构，r11 固定精选期次并重建每日分享；维护日期：2026-09-28。当前基准为用户确认的 CoDesign 保存版，版本、页面对应关系、r10 有意差异和实施状态见 [工程映射](design/CODESIGN-MAPPING.md)，未覆盖页面见 [补设计 prompt](design/CODESIGN-SUPPLEMENT-PROMPT.md)。重点是可阅读、可返回、可解释的界面，不是替换组件库。源码集中在 `apps\web\src`；组件文件位于其 `components` 子目录。

## 1. 设计目标与组件选择

读者首先应能扫描新闻、选择文章、理解要点与真实来源，再处理收藏等辅助操作。管理、采集和模型账户不应占据阅读页面主层级。

保留 Fluent UI 基础控件及其组合/键盘行为；阅读组合组件由项目直接维护。借鉴代码自有、API 一致的设计方式，但**没有引入 shadcn/ui、Tailwind、Radix 或 CVA**。换库不能代替实际截图和交互评审。

| 设计项 | 当前规范 |
| --- | --- |
| 配色 | 沿用 `--cp-*` 语义变量；浅色由 `codesign-theme.css` 映射至深绿 `#275D52`、灰绿底 `#F3F4EF`、阅读面 `#FCFCF9`。组件样式不写死浅色字面值，悬停、玻璃工具条、问题底色、地图底色等都走变量。深色仅保留旧兼容主题，未获得新的 CoDesign 深色设计；r10 只把深色次要文字提到 `#ABABAB`、选中底色改为不透明 `#47373A`，使兼容深色的文字对比度达到 4.5:1 |
| 字体 | 中文正文优先本机 PingFang / Noto Sans / Microsoft YaHei；标题使用 Georgia / 宋体后备，代码文字使用等宽字体；不加载外部字体 |
| 圆角 | 控件 6px、面板 8px、对话框 10px；普通文章采用细分隔线列表，不再堆叠 16px 圆角卡片；r10 起 Radar 不再提供摘要卡片视图 |
| 间距 | 以 4px 为基础节奏，统一密度；不靠额外空卡片制造“层次” |
| 操作层级 | 主、次、轻量、危险操作由 `ReaderButton` 统一；收藏和阅读价值不与标题争抢注意力 |
| 可追溯性 | 原题、来源、实际日期和来源内容范围不可因“美化”被删除或改写 |

## 3. 文字宽度与预览

外层阅读工作区最大 1120px，保留原型的水平留白。`ReaderStory` 的标题与摘要使用实际内容列的完整宽度，不再保留 160px 辅助操作列，也不把列表正文固定为 760px。顺序为标题、预览、来源元信息、阅读价值与收藏等辅助操作。长标题、展开的阅读价值、保存中和失败反馈都必须推动后续布局，不能覆盖下一条新闻。

展开的阅读价值使用所在列的完整宽度；长单词/链接安全换行。右侧阅读器最大 720px，其中内容最大 680px；全屏阅读也保留适合长文的行长，不把 1024px 的屏幕全部用作正文行宽。

**宽度、字符预算和行数是三件事。** `compactSummaryPoints` 最多取前两点并共享 240 字符预算；非 Copilot 紧凑摘录也有 240 字符预算。精选和公开摘要预览有两行显示限制，列表行也最多显示两行预览。打开文章才显示完整要点，不为填满宽卡片新增或重跑摘要。

调整时应测量正文实际宽度、空白与操作区位置，并使用足够长的真实/受控文本。仅证明 `scrollWidth <= innerWidth`，不能证明文字没有过早换行。长篇阅读区与列表预览可以有不同的行长策略，不能一律去掉所有阅读约束。

## 4. 焦点的归属

Fluent Select/Input 由组件自己的 `focus-within` 指示器提供焦点反馈，公开页的通用 outline 规则排除其原生子控件。Select 的底线固定为 2px，不能因为共用圆角而变成 5px 色带。阅读页签使用琥珀色外轮廓，去掉 Fluent 额外的黑色阴影焦点框；选中页签与键盘焦点仍是不同状态。

r12 起，焦点环统一使用 `--cp-focus-ring`（3px 不透明实线，颜色为 `--cp-focus`），在两种主题的页面、表面和侧栏色上都不低于 3:1（浅色 3.32–3.96:1，深色 6.67–8.71:1）。不得再用透明混色削弱焦点环。偏移量按场景而定：应用外壳 2px；登录页和公开阅读页 3px，会话确认页标题 4px；分段按钮彼此紧贴，用 −3px 内描边，避免盖住相邻按钮。Fluent Button 获得键盘焦点（`data-fui-focus-visible`）时会自行改描边颜色、改成 8px 圆角并加阴影。`reader-controls.css` 让 ReaderButton 保持静止时的圆角和描边、不加阴影；外壳内直接使用的 Fluent 按钮（如“不感兴趣”提示里的按钮）去掉 Fluent 的阴影，描边改为透明，由共享焦点环标示焦点。这些按钮静止时的 1px 描边在焦点时会消失，因为 Fluent 的类名无法区分按钮外观，无法可靠地还原。登录页标题加载时获得程序焦点（供读屏软件朗读），但不显示焦点框。分享页的“下载分享图”在忙碌时用 `disabledFocusable` 配合 `aria-busy`，不用 `disabled`，以免键盘焦点丢失；撤回确认与取消、错误提示里的重试，以及设置、来源、主题页的保存按钮仍用 `disabled`，列为待办。

普通标题、按钮、链接和 disclosure summary 仍有键盘焦点；不得全局使用 `outline: none`。选择器/输入框在鼠标点击后也可能匹配原生 `:focus-visible`，不能把这个选择器直接当作“仅键盘”证明。

规则调整还要保留特异性：目前通过 `:not(:where(...))` 排除 Fluent 子控件，避免新的选择器权重盖过标题已有的 4px outline offset。验证鼠标、Tab/Shift+Tab、方向键实际选择、明暗主题及 forced-colors，不仅比较一张点击截图。

云端已验证页面在窗口 hidden/blur 后继续保留，不因切到其他软件而换成全屏骨架；同时所有新的私有 API 请求立即进入会话闸门，返回 visible/focus 后静默确认账号。只有首次尚无已接受会话时显示公开几何骨架；确认持续超过 8 秒或临时失败时，才在保留页面上显示恢复对话框。恢复对话框、移动 Drawer 和其内隐私弹窗统一使用 Fluent/Tabster 模态栈，关闭后把焦点还给原控件。账号 ID 改变或401仍清空缓存并整页重载，不能为了避免视觉切换而放松跨账号隔离。

## 5. 响应式与阅读上下文

| 条件 | 预期 |
| --- | --- |
| 窗口宽度至少 769px | 176px 固定窄侧栏；主要阅读页保留同一套导航与下方工具入口；普通页面最大宽度 1120px |
| 不超过 768px | 56px 顶部品牌栏与 40px 带边框导航按钮；五个目的地在 250px（最多 85vw）侧栏底色抽屉中，当前入口保持选中底色，工具区置底；不使用底部固定导航或 72px 图标栏 |
| 不超过 768px（Radar） | 搜索、主题、来源各占一行；“更多筛选 · 时间与排序”与“清除筛选 / 应用更新”同排，展开后占满整行；主要触摸控件至少 44px |
| 不超过 768px（分段控件） | 分段按钮和雷达视图切换最小高 44px（`--ns-control-height`）；744/768px 触屏平板上，今日分享的三个按钮保持一行 |
| 不超过 640px（今日分享） | “复制文字版”和“下载分享图”两列等宽；支持系统分享时，“分享图片”独占下一行；按钮文字不折行 |
| 常规文章 / T1 深读，宽度至少 1025px | 固定右侧阅读器，列表和状态保留；不再使用固定 312px 深读队列宽度 |
| 常规文章 / T1 深读不超过 1024px | 聚焦阅读：阅读器从侧栏右侧覆盖内容区，768px 及以下覆盖整个视口；背景不可交互，焦点限制在阅读器内，保留关闭和前后篇 |
| 主题工作区不超过 1024px | 地图与结果上下堆叠；768px 及以下另有“地图 / 文章”切换；选中节点可滚动定位到结果，主动选文后聚焦文章，关闭后恢复主题和结果位置 |

右侧固定阅读器不能被祖先的 layout containment 改为相对容器定位。`reader-extras.css` 与 `useReaderDialog` 的面板定位、背景隔离、焦点和独立滚动规则具有行为意义，不是可随意删除的装饰。1024px 边界检查聚焦阅读与保留的侧栏，768px 边界检查抽屉导航，不能只看 390px。

返回应恢复打开者、选中主题/分组、列表位置和独立滚动区域。父控制器与子工作区不能互相抢焦点；无限分页后的个人状态更新必须覆盖已载入的所有页。

访客兴趣使用 `PageHeader.action` 及侧栏工具区入口，不新增第六个阅读目的地。受控 Fluent Dialog 中标题与关闭按钮同排；主题区独立滚动，取消/保存始终可达。窄屏单列，桌面双列，选择后才显示关注程度。Escape 只关闭兴趣编辑，恢复入口焦点，不顺带关闭背后的文章。完整设置、来源和个人兴趣工作流尚待补设计，不据此宣称管理端也已重做；r11 的每日分享页由工程沿用同一视觉系统设计，经独立 UI 评审，但不是 CoDesign 出图。

对话框的关闭目标至少 44×44px。复选框应对齐实际图形、文字及关注程度，不仅让外层高度相等；图形在触摸高度内居中。按钮保留共用外轮廓，移除 Fluent 聚焦态额外的 inset 阴影，避免双重焦点。兴趣对话框的这一覆盖在正常主题与 forced-colors 下都保留可见反馈；r12 起覆盖扩展到外壳内所有 ReaderButton 和直接使用的 Fluent 按钮（见第4节），这部分只在明暗两种正常主题下验证过。

勾选是草稿，保存成功才应用；清空选择仍需保存，损坏记录的重置有二次确认。失败时把滚动内容定位到错误提示，保留草稿及页脚操作。跨页面更新只提示，不自动重排本页或丢弃打开的草稿。说明必须区分“浏览器保存”和“推荐读取请求会携带主题”，不能声称兴趣从不发送。

## 6. 文案与状态

| 场景 | 应表达 | 不应表达 |
| --- | --- | --- |
| 展开文章 | 阅读要点与来源内容 | 未取得全文却写“打开原文阅读” |
| 阅读价值 | 现有摘要对内容价值的简明解读；没有则不编造 | `article-value-v1`、基础值、类型和加分日志 |
| T1 技术识别 | 实际分类/栏目/规则依据，明确不等于质量认证 | 技术标题命中即“已验证深度技术” |
| 加载 | 对应布局骨架，保持已知标题；可关闭或切换详情 | 还没返回数据就显示“0 篇” |
| 空结果 | 当前条件下无材料，并保留可调整的条件 | 把接口失败显示成无新闻 |
| 失败 | 明确错误与一次可执行重试；保留阅读上下文 | 无限重试、静默旧缓存或成功样式 |
| 开始深读 | 真实首篇标题/来源/预览与起始按钮，下面是其余队列；“已打开”不是“读完” | 空白巨型详情框、虚构 2/5 进度或自动打开第一篇 |
| 周报主题 | 初始选择主题，按真实分节与成员显示文章，也可以选择“全部主题” | 不同主题都展示相同示例文章，或把历史晨报伪装成滚动周报 |
| Radar 双任务 | 默认仍是 72 小时 / 推荐；显式“最近 24 小时”使用 24 小时 / 最新；切换保留主题、搜索等条件 | 暗改默认权重、把来源等级当内容类型，或声称知道未查询的更新数 |
| 晨报分享 | 精选工具条的“生成今日分享图”进入 `/share`；阅读面板可复制单条标题、概述与原文链接 | 每个晨报条目重复展示分享卡片 |
| 每日分享图 | 已选/上限、实际排序依据、补读标注发布日期、图中链接不可点击需另发文字版、图片只在本机生成 | 把模型摘要说成事实核验，暗示图片会上传或生成公开链接 |
| 来源管理 | 来源状态和用户可理解的说明 | 把目录导入出处等审计文字铺满普通列表 |

主动收藏/不感兴趣应有保存中、失败、撤销反馈；公开版的反馈仅属于当前浏览器。2026-09-22的反馈组件使用正常鼠标指针、局部静态下划线，以及“收藏中 / 取消中 / 移出中 / 撤销中”的明确待确认标签，不让整个阅读区呈现繁忙鼠标，也不在服务器确认前伪装已保存。保留乐观图标、`aria-busy`、可聚焦的禁用状态、同一事件跨控件防重复、错误回滚与重试。

列表、右侧阅读器与撤销提示共享同事件的在途状态。其他控件确认撤销后，原撤销提示也必须同步消失；不能因为两种mutation变量形状不同而导致白屏，也不能让旧事件的错误出现在新事件提示中。反馈只补当前缓存中的阅读状态，不自动刷新整页或重排正在阅读的文章。该失效策略原本已是 `refetchType: "none"`，不能把此次后端慢查询归因于“收藏等待整页网络重拉”。

精选按“期”展示：一期对应一次晨报，同一期24小时内顺序、摘要和截止时刻不变；工具条显示本期日期、篇数、北京时间选文截止点和“下次更新”时刻。来源只有日期时只显示日期，有准确时间才显示时间。晨报生成期间先显示上一期并说明正在生成，完成后自动换成新版并用状态文字告知；分享页不在勾选途中替换内容，只提示“换成新版”。当天不足5篇时说明“符合标准的内容较少”，而不是用旧闻凑数；没有达标内容时给出新闻雷达与来源采集入口。不触发采集；历史版本使用响应中的保存窗口，不拿浏览器当前时钟补造。危及数据的管理操作需确认和取消路径，但不得为了截图在站主日常数据库上试验。实际发布状态另见Azure手册，不把源码契约当成已上线证明。

## 7. 独立 UI Critic 如何运行

角色定义在 `.github\agents\ui-critic.agent.md`，名称为 `newsscout-ui-critic`。它是**只读的独立评审角色**，不是运行中的服务，也不是设计师人工批准或无障碍认证。

`scripts\capture-ui-review.cjs` 和 `npm run ui:review` 只负责收集浏览器截图/指标，不调用 AI、不输出自动评分、不修改代码。Coding Agent 或维护者显式启动独立评审，之后负责修正并请同一评审者复查。

1. 明确本次变更范围、受影响入口和个人/公开差异，保存同尺寸、同内容的前后对照。
2. 构建候选，按 [测试指南](TESTING.md) 取得交互证据；截图目标必须是声明只读的公开网关。
3. 把目录、manifest、变更范围和行为证据交给独立 Critic；没有看过的范围标为未评审。
4. 按 P0/P1/P2 修正具体问题，并按同一 ID 复查；不能把测试通过当视觉通过。
5. 发布后再看真实 HTTPS 入口，确认仍是被评审的构建；保留记录而不覆盖旧目录。

```powershell
# 综合：阅读入口、Radar 两种视图、主题阅读、代表性详情与恢复状态
npm.cmd run ui:review -- --base-url http://127.0.0.1:5190 --output tmp\ui-reviews\my-full-review

# 专项：1440 / 1920 / 390，明暗主题、展开阅读价值、鼠标/键盘选择器焦点
npm.cmd run ui:review -- --base-url http://127.0.0.1:5190 --scope width-focus --output tmp\ui-reviews\my-width-review

# 专项：兴趣入口、编辑/滚动、真实推荐与主题结果、模拟存储失败
npm.cmd run ui:review -- --base-url http://127.0.0.1:5190 --scope interests --output tmp\ui-reviews\my-interest-review
```
