# 阅读与分享访问契约

适用版本：0.2；维护日期：2026-09-24。必须区分完整应用的 Azure 认证邀请测试、可信本地模式，以及旧 Dev Tunnel 匿名只读门户。“公开地址”不意味着只能使用缩水阅读版，也不意味着所有私有数据可以匿名读取。

**当前上线边界（2026-09-24）：r11邀请预览，Ready revision `newsscout--0000008`；仍只有1个用户明确批准的身份。** 今日精选按事件重要性与价值排序，晨报在北京时间6点固定为一期；新增“今日分享”，可一键下载当天约10条新闻的长图，图片在浏览器本地生成、不创建公开链接。新闻雷达（列表与主题地图）、深度阅读、每周回顾、收藏与共用阅读器沿用同一账号门禁、既有403修复和收藏局部待确认状态。匿名登录页首屏传输约142KiB，前门稳定首次内容绘制约1.2–1.7秒；事件列表的后端耗时未在本轮处理。云端schema推断为29（迁移只改SQL函数），原设置与历史晨报保持，日常本地实例已停止且仍为27。全历史探索仍有慢路径；完整耗时口径、5000共享额度及剩余live范围见 [Azure手册](AZURE-PREVIEW.md)。第二真实账号及其余分享/导出流程未获全量live验收，旧Dev Tunnel已退役，此为非生产预览。

## Azure 试用者契约

实现入口：`services\cloud-host`、`services\api\src\auth.rs` / `scoped_db.rs` / `reader_account.rs`、`apps\web\src\auth.tsx`。Azure 不是将旧5190网关改成全量透传：平台 EasyAuth、Node 可信代理、Rust 权限校验和 PostgreSQL 事务角色/RLS 共同构成边界。试用者不用提交 GitHub token；模型由独立服务账号提供，不能通过云端设置页改模型或额度。

### 登录、兴趣、来源和采集

- 登录并获准入后使用同一完整阅读与工作台。收藏、打开/曝光、兴趣、来源覆盖、自定义来源、晨报与草稿属于本人；不继承站主兴趣，不把其他人的私有来源材料合并进来。云端账号与旧匿名浏览器记录没有自动迁移或同步。
- 通过 `/api/v1/session` 建立会话；私有 API 不接受匿名用户。写请求还需要精确 Origin 和该用户的 CSRF token。跳过前端直接请求设置或他人资源不会获得权限，账号过期/切换须重新建立会话并清理私有缓存。
- Microsoft认证与应用批准是两件事。已部署的 `approved_accounts` 当前只批准1个身份，名单不公开；同事先登录再申请。只按本人实际申请编号中的不可变tenant/object UUID对批准，不匹配邮箱、显示名或整个租户。新环境默认空名单会拒绝全部私有API；组织管理员审批是另一层要求，不要求关闭组织安全策略。
- 有效但未获邀的身份在创建应用账号前收到403 `invitation_required` 和本人的 `invitationKey`。页面显示“这个账号还未获邀。”、只读且可选中的“申请编号”，须**手动发送给维护者，不会自动提交申请**；另有“已获批准，重新进入”、切换账号及隐私链接，重新进入不自行批准。真实首位用户已完成OAuth并提供本人编号；当前批准范围和证据见 [Azure手册第1节](AZURE-PREVIEW.md#1-带日期的-rollout-状态)。
- 每次私有请求重新检查成员资格；撤销后的403使旧document、mutation和缓存被清除并重载，不继续显示旧账号资料。显式发布快照及健康检查保持匿名例外，撤销账号访问不会自动撤回已经公开的快照。
- 公共来源目录是共享种子；启用、暂停、确认和间隔等用户选择使用本人覆盖，不修改其他读者的选择。新增来源及其衍生材料按账号私有，但端点仍须符合公开 HTTPS 与来源许可策略；不是私网抓取或携带第三方凭据的入口。
- 采集/正文补全提交异步任务，实际维护调用返回HTTP200和job对象；前端也接受202，不能据此声称服务器返回202。每批最多100来源、每用户6次/小时、最多一个活动任务，同源全局claim间隔2分钟。查询 `/api/v1/ingestion-runs/{id}` 只读本人任务，重复提交可返回已有job，无取消接口。返回任务不代表完成；已验证的两次维护调用使用真实OAuth建档的批准profile，不是浏览器点击证据。

### 分享与匿名读取

r11 起分享入口是每日分享页 `/share`：按所选顺序从当期精选的24小时内容中预选前10条（补读默认不选，总数最多15条，可增减），顺序可选“AI 相关优先”或“精选顺序”，选择保存在本浏览器；每条使用该期已有摘要要点截取几句中文概述，后接去掉跟踪参数的原文链接。图片由浏览器用 canvas 在本地生成并下载，不上传、不写入 `reader_shares`，也不新增模型调用；也可复制带可点击链接的文字版，支持系统分享的触屏设备可直接分享图片，阅读面板可复制单条标题、概述与原文链接。页面固定打开时的那一期，新一期生成后只提示“换成新版”，不会在勾选途中替换内容。补读条目标注原发布日期。旧素材草稿编辑器已移除，`/shares` 与 `/share/:id` 重定向到 `/share`。

此前显式发布的匿名 `/p/:id` 继续通过 `GET /api/v1/public/shares/{id}` 读取服务端事务内冻结的 `published_document`；每日分享页列出本人已发布链接并可撤回。匿名响应只包含显式选中的发布文档，不返回原草稿的未选文章、编辑器状态、账号、阅读反馈或整个私有新闻库，也没有匿名分享索引。每次读取都会检查撤回状态；已发布快照不能再编辑，撤回后不能重发同一快照。撤回不能收回别人已经保存的图片、文字或 JSON，下载的分享图也不受撤回影响。

登录页、`/privacy`、静态资源、`/health` 和明确发布的快照允许匿名，不代表 `/api/v1/events`、本人草稿/来源/账号数据匿名可读。平台 `AllowAnonymous` 用于上述公共页面，私有 API 的实际授权在应用内强制执行。

### 隐私、使用事件与导出

- 登录标识、显示名、兴趣、收藏/打开/曝光、来源和草稿用于提供服务。必要的运行/安全日志与可选产品使用事件分开，关闭可选统计不会抹掉正常阅读数据。
- 可选使用事件默认关闭；当前前端实际只发 `page_view` 和有限页面类别。后端允许有限 `action` schema 不等于已全面埋点，更不是完整分析面板。事件按账号保存，不应宣称不可回溯的完全匿名；不收集搜索词、新闻正文、邮箱、密码或 token。
- 关闭同意会在事务内删除该用户已有可选事件；事件配置30天保留，由后台定期清理。运行日志/Insights 使用有限路由模板、结果和耗时，保留30天；必要日志不随可选统计开关删除。
- “导出我的数据”只返回本人 JSON，包括兴趣、状态、曝光、草稿/分享、自定义来源与来源覆盖、本人晨报索引及账号显示/同意信息。不是全库备份，不导出其他人、服务凭据、系统设置或整库抓取正文。
- 导出上限20 MiB、每用户每小时2次提交。服务先写入 Entra RBAC 保护的私有 Blob 归档，再经当前已认证请求返回 JSON；不发公开 Blob URL、账号密钥或 SAS。私有副本配置7天生命周期清理，异步执行不保证第7天整点删除，也不等于已使用 private endpoint。
- **没有自助账号删除**；需要删除时联系邀请你试用的维护者。不要在邀请测试中录入敏感/保密材料或第三方凭据。

## 旧 Dev Tunnel：给匿名试读同事的说明

**旧隧道已退役。** 以下保留 `services\public-reader\server.cjs`、`apps\web\src\pages\PublicReader.tsx`、`apps\web\src\public-reader.ts` 的历史5190契约，不表示当前在线或要求重新启动，**不将其只读限制套到Azure认证应用**。

这是读取站主已收录材料的试用门户，不要求访客连接 Copilot，也不会因访客打开文章而采集或调用模型。采用匿名隧道时，任何获得地址的人都可能访问；它不是只允许特定同事登录的受控工作区。

| 阅读入口 | 用法 |
| --- | --- |
| 今日精选 `/` | 看当前精选及最近 24 小时入口；设置访客兴趣后按兴趣选文。“晨报版本”仍可选择实际已保存日期 |
| 新闻雷达 `/radar` | 双任务为最近 24 小时 / 值得阅读；切换列表、主题地图（r10 起移除摘要卡片，旧 `?view=cards` 回落到列表）；时间范围、排序及开发构建位于“更多筛选 · 时间与排序” |
| 深度阅读 `/reading` | 从真实首篇主动开始，再继续“接下来”队列；保留 T1 来源、内容与时间范围筛选 |
| 每周回顾 `/weekly` | 先选择真实主题或全部主题，再回看滚动一周内的对应材料；不额外生成一篇整周模型总结 |
| 收藏 `/saved` | 查看这个浏览器保存的文章；不是站主的个人收藏库 |

宽度超过 768px 时使用176px窄侧栏，较窄屏幕使用顶部导航抽屉，五个阅读目的地不变。点击文章标题后，宽度超过 1024px 时在固定右侧阅读器中展开，较窄屏幕聚焦文章；关闭恢复原列表的状态、焦点和位置。主题地图在 1024px 及以下与结果上下堆叠，而不是挤成两个窄栏。

只有实际收录了相应材料时才提供来源内容切换；原站链接仍然跳转发布者页面。来源只提供节选、节目说明或文字稿链接时，不把它叫作已取得全文或已完成转写。CoDesign 设计与缺页范围见 [工程映射](design/CODESIGN-MAPPING.md)，文档中的当前代码契约不代替具体站点的部署记录。

收藏、不感兴趣和打开记录按浏览器及网站地址隔离；换浏览器、无痕窗口、域名或清除站点数据可能得到不同记录。打开不等于读完；公开反馈不写入站主偏好，不训练访客专属推荐。

### 修改自己的兴趣

使用页面标题旁的 **兴趣主题**，或侧栏 / 导航抽屉中的 **兴趣设置**，从当前分类支持的 13 个主题中选择，设置普通关注、重点关注或优先关注，然后 **保存并应用**。勾选过程只是草稿，取消或 Escape 不会保存。清空选择并保存会恢复共享推荐，不删除收藏和阅读记录。

兴趣调整当前精选、Radar 推荐排序及主题工作区的推荐样本/结果，不是只显示所选主题的硬筛选。内容资格、来源质量和多样性限制仍生效；最新优先、来源与热点分、深读、周报和已保存晨报不改为兴趣排序。不会生成新摘要或新晨报存档。

兴趣持久保存在当前浏览器；**选中的主题会随读取请求发送给服务端，用于这次选文**，不是“从不离开设备”。服务端不建立访客兴趣档案，也不覆盖站主兴趣。不同浏览器/站点地址不共享这份设置；同一浏览器其他页面的改动要明确应用，本页不会自动跳到另一套推荐。存储失败保留草稿；损坏记录不会自动覆盖，重置需要再次确认。

## 阅读批次、主题与历史

- r11 起精选按“期”展示：北京时间晨报时刻（默认06:00）后显示当天保存版，之前显示前一天的，同一期24小时内排序和内容不变，并标出本期截止时刻和“下次更新”时刻。主列表只收截止前24小时的合格内容，严格按综合分从高到低，前5篇为今日重点，其余为更多值得读；不再为当天发布预留名额，也不强行补入讨论、未确认来源或待处理摘录。过去7天内未入选过、重要性与原文价值都达标的较早内容放入“值得补读”，最多3条。当前部署版本见本文顶部与Azure手册。
- 新一期生成完成后页面自动换成新版；生成期间先显示上一期并说明正在生成。旧公开版“更新内容”才重新读取当前精选。切回窗口不触发采集。条目显示来源实际提供的时间精度；较早日期仍可能属于截止前24小时，收录时间不能代替发布时间。旧投影缺少截止字段时明确提示，不猜一个时点。
- Radar 进入页面时创建规范化 UTC `asOf`，同一批次后续分页复用；“应用更新”或明确应用新兴趣才刷新该批次。兴趣参与全体候选的服务端排序后再分组、分页，不是在已载入的 40 条里重新排序。比较结果时必须同时对齐筛选、排序、兴趣和时间锚点。
- Radar 默认仍是72小时 / 推荐；显式“最近24小时”采用24小时 / 最新，“值得阅读”采用72小时 / 推荐，两者保留主题、搜索和等级条件。应用更新不触发采集，也不显示未查询的新增计数。
- 主题图基于最多 100 条匹配新闻的关键词共现；图谱样本量不等于右侧可分页结果的总数。初始不默认选择第一个主题，点选节点才缩小结果范围，清除后恢复全部主题。
- T1 队列固定 `T1 + blog + newest`，默认技术范围和过去 720 小时。目录可以保留已暂停来源以阅读已收录历史，不能把“可选来源”误解为仍在自动采集。
- 周报主题来自服务端分节，`weekTopic` 只记录当前界面选择，不变成新的公开 API 参数；前后篇限制到所选主题的实际成员，历史晨报仍走独立的保存版入口。
- 公开分页只接受 `offset <= 1000`。这是页起始偏移限制，不是“全库最多 1000 篇”；达到上限时不能把继续加载失败显示成完整历史结束。
- 历史晨报先验证日期出现在已保存目录中，再读取对应快照。没有存档的日期返回缺失，不调用今天的生成逻辑补一个版本。
- 从历史晨报打开文章时展示当前已收录详情，并保留版本提示；快照列表中的标题、摘要、顺序和原有成员不随之重写。

### 组件发布与分组标题

同一官方项目的 SDK、CLI、SDK Provider 只有具备明确共同改动依据时才按客户端分组；插件等已有家族仍遵守各自边界。新分组的 `coverage.method` 为 `release-family-v2`，`relation` 仍为 `release_family`，不增加访客权限或查询参数。各组件保留独立版本、原有摘要、来源与阅读入口；不能将一组视作一篇新生成的综合摘要或多个独立来源的互证。

组标题尽量指出共同的实际变化，例如“安装统计”“遥测”“调用来源标识”；材料不支持这些主题时，使用组件名称而非泛称“集中更新”。Node CLI 与 Node SDK 分别列出。推荐排序只选择主条目，不改变同一候选集合的发布批次；关键词、时间或等级筛选仍可能减少可见成员，只有一项时恢复单篇。

公开版与个人版使用相同分组规则；访客收藏/隐藏仍只影响本浏览器。历史保存组保留原来的 `v1` / `v2` 标题和成员。过去24小时是来源时间筛选，不等于过去24小时的采集记录；推荐排序也不保证当天材料出现在第一页。

## 旧匿名网关 HTTP API

以下只说明旧 `/beta/api` 网关，不是 Azure 的认证 `/api/v1` 契约；七月规格中的 API 草案也不能代替实现。旧网关所有 API 请求限于 `GET` / `HEAD`，不接收请求正文；`HEAD` 向上游也只做读取。

| 路径 | 返回内容 | 查询参数 |
| --- | --- | --- |
| `/health` | 服务标识及 `readOnly: true` | 健康检查 |
| `/beta/api/events` | 公开文章/分组列表、`nextOffset` 及返回数量字段 | Radar 参数 |
| `/beta/api/events/{uuid}` | 单篇公开文章及允许的来源材料 | 可选 `interests` |
| `/beta/api/explore` | `sampleSize`、`limit`、`meaning`、`nodes`、`edges` | Radar 参数；校验后移除文章 `sort/limit/offset` |
| `/beta/api/brief` | 当前共享或兴趣精选 | 可选 `interests`；有兴趣时可带 `asOf` |
| `/beta/api/briefs` | 已保存日期、生成时间、条目数 | 不接受查询参数 |
| `/beta/api/briefs/{YYYY-MM-DD}` | 指定日期的真实快照 | 不接受查询参数；须在已保存目录内 |
| `/beta/api/weekly` | 滚动周报、版块及有序条目 | 不接受查询参数 |
| `/beta/api/reading/sources` | T1 博客来源的 `id/name` | 不接受查询参数 |
| `/beta/api/reading` | `items/nextOffset/asOf`，需要时含 `paginationLimited` | 深读参数 |

### Radar 参数

未知参数和重复参数被拒绝，不采用“最后一个值覆盖前一个”的隐式规则。

| 参数 | 接受范围 |
| --- | --- |
| `q` | 最多 200 个 JavaScript 字符单位的搜索字符串；拒绝 U+0000–U+001F |
| `topic`、`facet` | 各最多 80 个 JavaScript 字符单位；拒绝 U+0000–U+001F |
| `tier` | `T1`、`T1.5`、`T2` |
| `hours` | 整数 0–720；0 表示不限日期，events 默认 72 |
| `limit` | 1–40；events 省略时默认 30，当前 UI 明确传 40 |
| `offset` | 0–1000 |
| `sort` | `recommended`、`newest`、`score`；events 默认 `recommended` |
| `asOf` | 必须与 `new Date(value).toISOString()` 完全一致，例如 `2026-09-16T12:00:00.000Z` |
| `includeEngineering` | `true`、`false` |
| `interests` | 可选、非空的规范主题 ID/权重列表，规则见下节 |

events 网关强制 `coverage=true`，访客不能自行要求私有查询选项。直接调用者需要固定批次时应显式提供并复用 `asOf`；该列表响应不像深读响应那样回传它。

### 请求内兴趣参数

例：`interests=agents:100,psychology:80`。ID 来自 `shared\reader-interest-topics.json`，与现有文章分类一致，不接受任意中文标签、自定义 ID、重复 ID 或重复查询参数。最多 13 项，解码后的参数最长 512 字符；权重是 0–100 的规范整数，拒绝小数、符号和前导零。界面提供 50/80/100 三档，未选主题不写入参数；无兴趣时应省略参数，不能传空值。

网关按 ID 规范排序，并以完整上游路径缓存，包含兴趣和时间锚点。列表、主题数据源、当前精选和相应文章详情的前端缓存也包含兴趣；切换时旧的在途分页不能混入新结果。历史晨报、周报和深读接口拒绝兴趣参数。

后端以临时画像及空读者身份重用编辑评分，兴趣仍占 20%，其他权重不变。`readerProfileApplied` 是私有响应中的协议确认，不是认证凭据，也不透传给访客；旧 API 忽略兴趣参数或返回保存版冒充当前兴趣精选时，网关返回 503，不静默使用站主结果。

浏览器记录分别使用 `newsscout-public-interests-v1`（`version: 1`、`topics`）和 `newsscout-public-feedback-v1`，两者不相互覆盖。公开接口仍没有 `PUT /me/interests` 或其他管理写入口。

### 深读参数

仅接受 `source/scope/hours/limit/offset/asOf`；不允许改写来源等级、类型、排序或追加私有筛选。

| 参数 | 接受范围 / 默认值 |
| --- | --- |
| `source` | 合法 UUID，且必须属于公开 T1 博客目录；省略为全部 |
| `scope` | `technical` / `all`；默认 `technical` |
| `hours` | `720` / `0`；默认 `720` |
| `limit` | 1–40；默认 40 |
| `offset` | 0–1000；默认 0 |
| `asOf` | 规范 UTC ISO 字符串；首次省略则由网关产生，后续分页复用返回值 |

页偏移前进、每页文章 ID 唯一性和结果类型受网关检查；异常页被拒绝，不静默修剪成正常结果。`paginationLimited` 表示受公开浏览预算限制，不是数据库已没有材料。

## 字段和访问边界

公开文章按允许列表投影，保留条目身份、可选内容版本/阅读标题、主题、来源时间、摘要、必要的摘要归因、裁剪后的编辑信息及来源。旧快照缺少可选字段时保持缺失，不补造标题或版本。

编辑信息仅保留 `policyVersion/contentKind/reason`；这些字段仍可能包含规则语境，不能宣称所有内部式文字都从响应中删除。

不向访客返回站主收藏/打开/不感兴趣状态、个人推荐分、个人相关性理由、账号或来源管理配置。编辑信息中的规则说明不等于面向读者的“阅读价值”；UI 使用已有摘要解读，不把内部分类/加分日志直接当作解释文案。

来源链接只允许符合公开链接规则的 HTTPS 地址；`readingContext` 保留允许的正文、节目/评论字段及实际范围，不把不可访问链接或未经取得的全文伪造为可用内容。公开页面不能借参数调用私有采集、账户、摘要、分享管理或任意转发接口。

## 运行限额与失败

| 约束 | 当前实现 |
| --- | --- |
| 上游地址 | loopback HTTP origin，仅 `127.0.0.1` / `localhost` |
| 上游同时请求 | 最多 4 个；超出不进行无界排队 |
| 上游请求超时 | 20 秒；不跟随重定向 |
| 上游 JSON | 最大 8 MiB |
| 成功读取缓存 | 30 秒，最多 128 个键；失败后不以过期缓存冒充成功 |
| 公开 API 请求额度 | 单个网关进程共享每分钟 600 次；不是每个访客独享 |
| 入口与静态资源 | 页面默认不缓存；带哈希资源可缓存 86400 秒，来自本次发布副本 |

不支持的筛选返回 400；未开放路由、未保存日期或不存在内容返回 404；写方法返回 405；请求过多返回 429；上游不可用、投影不合法或超出运行边界返回 503。不能把这些失败当成空列表。

该网关有静态资源和响应头保护，但不是生产多租户安全边界的替代品。运行电脑、个人 API 和公开启动器都必须保持运行。发布、健康检查和日志定位见 [运行与发布手册](OPERATIONS.md)。

## 常见差异的解释

| 现象 | 应先区分什么 |
| --- | --- |
| 公开内容比本地少 | 当前精选还是存档、已载入页数、筛选/排序/兴趣/时间锚点、本浏览器隐藏项、公开分页上限 |
| 修改兴趣后某篇仍未靠前 | 是否保存并应用、是否使用当前精选/推荐排序、文章当前分类、资格与质量；兴趣不是硬筛选或最高优先级保证 |
| 少了整个“主题关联”页签 | 先比较实际构建与能力矩阵；过去确实有实现缺口，不能一概归因于缓存 |
| 最新文章未出现在晨报 | 晨报资格、摘要状态、保存版日期与固定阅读批次；不是打开网页就触发采集 |
| 收藏与本地不一致 | 两者是不同存储；同一浏览器的 localhost 与隧道域名也不是同一站点 |
| “原文”只显示少量文字 | 该条实际只取得部分材料；原文入口可继续跳转发布者，不声称完整阅读 |
| 隧道地址仍在但页面打不开 | 地址存在不等于有运行中的 host；检查本机服务与当前运行记录，不改为暴露私有端口 |
