## 文档与事实的优先关系

1. 当前源代码、增量迁移和运行脚本定义实际行为；当前运行配置需从本机设置和运行记录读取。
2. 专题文档说明当前契约，`PROJECT-STATUS.md` 和 `CHANGELOG.md` 记录带日期的交付范围。
3. 截图、测试输出和发布记录只证明其对应版本、时间和范围，不保证此后一直在线。
4. `V0-SPEC.md` 保留原始规划。正文中的拟议 API、权重、调度时间和未来能力不得直接当作已实现功能。

Azure最终状态由新鲜的 `tmp\azure-preview-20260920\release-status.json` 安全聚合驱动，并在 `AZURE-PREVIEW.md` 第1节说明证据边界。真实浏览器OAuth/读取、维护通道采集、初始内容快照和后来应用预算是不同事实；初始20次上限不能覆盖聚合中较新的5000配置。不得复制私有身份名单或把mock/控制探测当真人流程。旧CoDesign/隧道交付记录保留为历史，不转写成Azure验收。

示例中的文件系统路径使用 Windows 写法；命令默认从 ScoutNews 项目根目录执行。文档中的域名、端口、版本标识和样例日期各有适用范围，不能把某次发布的进程 ID 或模型额度抄成新环境默认值。

## 修改时同步哪些文档

| 变更类型 | 必须同步 |
| --- | --- |
| 新增、移除阅读能力或改变公开权限 | `PROJECT-STATUS.md`、`PUBLIC-READER.md`、根 `README.md`；确认交付后更新 `CHANGELOG.md` |
| 服务、数据模型、排序或快照语义变化 | `ARCHITECTURE.md`、根 `README.md`；仅概念改变时更新 `CONTEXT.md` |
| 端口、环境变量、启动与发布方式变化 | `OPERATIONS.md`；Azure 同步 `AZURE-PREVIEW.md`，配置模板/测试确有变化时再同步相应文件 |
| Azure 部署或现场验收进展 | 统一更新 `AZURE-PREVIEW.md` 第1节，明确版本、时间及未验证项；其他文档保留带日期快照并引用该节。最终准入/产品契约交接后再同步相关契约正文，不把候选当成已交付 |
| 布局、组件或交互契约变化 | `UI-DESIGN.md`、相关 UI 用例；评审职责变化时更新 Critic 角色 |
| 新验证方式或已确认交付 | `TESTING.md`、`CHANGELOG.md`，记录准确的范围及失败/阻塞 |

不为补文档重置数据库、重跑历史摘要、修改来源决策或重新发布服务。不把 `.env`、账号信息、数据库备份、个人反馈或完整运行日志放进公开文档。
