## 1. 导航与身份边界

### 1.1 站主本地工作区

在现有阅读导航之外安排低干扰的“管理”分组或等效入口，不抢占五个阅读主入口：

| 入口 | 现有路径 / 任务 |
| --- | --- |
| 阅读与模型设置 | `/settings`：采集日程、账户、模型、自动摘要、用量与队列 |
| 来源与采集 | `/sources`：已接入来源、关注名单、覆盖与管理 |
| 我的兴趣 | `/topics`：站主数据库中的主题、启用状态与权重 |
| 分享草稿 | `/shares`：本地草稿库；`/share/:id`：继续编辑和导出 |

分享工作台要有清楚的“返回本地草稿库”，并保留从文章、简报、周报进入的语境。阅读面只保留必要的简短状态和“队列与用量”入口，详细诊断放到管理页。

### 1.2 公开阅读工作区

公开读者只获得阅读与**当前浏览器的兴趣设置**；不能进入站主的设置、来源、账户、采集、摘要队列、兴趣数据库或分享草稿工作台。不要仅靠把按钮置灰来制造“任何访客都能管理”的暗示。

“连接本机 GitHub/Copilot”是站主连接模型能力，不是给公开读者注册 NewsScout 账户。不要设计密码登录、访客云档案、团队成员管理或社交平台账号绑定。

## 2. 设置：阅读日程、账户、模型、用量

建议按“阅读节奏 → 自动摘要 → 账户连接 → 用量与最近任务”组织，可用锚点或分节；不必做成四个新的顶级页面。

### 2.1 晨间阅读节奏

- 采集方式只有“每日晨间采集”和“按来源间隔采集”。每日模式选择上海时间 `00:00–23:00` 的整点；不增加任意时区、分钟级 Cron 或星期规则。
- 精选条数上限保留现有 `5 / 10 / 15 / 20 / 25 / 30` 选项；后端允许 5–30 的整数。另有“包含健康的观察来源”，必须说明观察来源并非已经确认的信源。
- 有保存、未修改不可提交、未保存修改、保存中、放弃修改、校验失败、保存失败保留草稿、保存后回读状态。保存日程不等于立即开始采集，也不覆盖历史晨报。
- 展示“下次计划、上次成功采集、最新来源发布时间”；三者不可混成“最后更新”。时区标为上海 / 北京时间。
- 本日运行支持“采集中、准备摘要、已就绪、部分就绪、失败”，显示计划时点、实际开始、来源成功/失败和可读说明；没有运行记录时不要补出成功状态。
- 明示需电脑和应用保持运行；错过既有计划可在恢复后补采。如果当日时点已过才首次启用或修改日程，首轮从次日开始。手动采集入口与日程设置分开。
- 代码默认每日 06:00、精选上限 20、包含健康观察来源，是**产品默认值**，不是当前用户的设置；已保存值以服务端为准。

### 2.2 模型账户

- 账户卡显示连接状态、可用性、登录方式、本次探测说明、最近验证时间、已选模型与探测到的模型。原型用“示例账户”等脱敏占位，不复制真实账号或凭据。
- 支持“连接本机 GitHub/Copilot、重新探测、断开”。只有服务端明确返回 OAuth 已配置时，才显示“改用 OAuth App 授权”；不是让所有用户自行填 token 的配置页。
- 断开仅影响 NewsScout，不退出全局 GitHub/Copilot 登录，不删除阅读内容。为断开提供清楚的影响说明与取消路径；不要声称断开能撤销已经发生的模型调用。
- 连接成功不等于所选模型一定可用。已选模型不在探测列表时，显示原因并由用户明确选择，不静默换模型或提供方。
- 明示：若自动摘要已开启，账户、模型、额度恢复可用后队列可能继续并消耗所选账户用量。阅读原文不需要模型账户。
- 提供未连接、连接中、已连接可用、账户不可用、已选模型不可用、探测失败、断开失败、OAuth 返回失败等状态；成功消息不能覆盖仍然存在的不可用原因。
- Azure OpenAI 在当前版本仅为“暂不支持”的能力说明，没有浏览器密钥配置或调用能力，不能画成可切换的生产提供方。演示与隔离环境不访问本机凭据、不调用真实模型。

### 2.3 自动摘要与用量

- 控件只有：自动中文摘要开关、精确模型选择、滚动 24 小时调用上限、保存 / 放弃修改。模型列表保留已保存模型、产品默认模型和实际探测结果；不可用项应可理解，不自动选中其他模型。
- 上限为 `1–5000` 的整数；当前代码默认 `20` 次 / 滚动 24 小时，默认模型标识为 `gpt-5.6-terra`。它们是代码默认，不是“今日剩余额度”“最新模型”或账号可用性保证。
- 手动与自动调用共用预算，失败调用也计入。显示已用 / 上限、最早额度恢复时间或“暂无记录”；不是每天零点重置，也不是供应商账单或精确金额。
- 关闭并保存只阻止启动新任务，正在运行的任务仍会完成；暂停不删除队列和已有摘要。不要提供没有接口支持的“立即终止所有任务”。
- 阻塞原因分别呈现：用户暂停、演示、隔离、账户不可用、模型不可用、额度达到上限。每种原因给出真实可行的下一步，不统一变成“重试即可”。
- 队列显示排队中 / 生成中 / 已失败 / 已完成的全局数量，以及 AI 摘要与待处理来源内容数量。近期记录显示文章入口、状态、模型、尝试次数、最早下次尝试、最近错误；明确“近期有限记录”，不是完整队列浏览器。
- “重试失败任务”只重新排队，返回实际入队数；没有失败任务时不可点击。重试不提高预算、不保证立即生成，不改写历史快照。支持重新排队失败和“没有任务需要重试”。
- 状态刷新失败但有缓存时保留上次数据并标注过期；不能把旧数值装成实时监控。所有账户 / 额度 / 队列为空或读取失败的情况都要可继续阅读原文。

## 3. 来源与采集：接入、生命周期、健康、关注名单

### 3.1 已接入来源

- 保留“已接入来源 / 关注名单 / 覆盖与管理”三个任务视图。来源筛选包含名称、发布方、域名或主题搜索，等级 `T1 / T1.5 / T2`，适配器，生命周期；显示结果数 / 全部数、已应用条件和清除筛选。
- 页内切换、刷新、返回后能恢复 URL 中的筛选状态。搜索无结果与尚无来源不同；读取失败不能呈现成空数据库。
- 每条来源显示名称、发布方、公开订阅入口、主题、等级、内容类型、适配器、生命周期、上次成功、连续失败次数和最近错误。等级、类型、适配器和健康状态是不同维度，`T1` 不能改名为“博客”。
- 生命周期为“观察中 / 稳定 / 已暂停”。成功时间为空时为待首次成功；观察来源可以健康，稳定来源也可能采集失败。不要用一个绿色标签同时承诺可信、完整、及时。
- 现有动作：暂停 / 恢复采集、单源刷新、保存间隔、将符合条件的观察来源确认为稳定。恢复保留此前生命周期；暂停不等于删除来源或历史内容。
- 确认稳定须先成功采集、当前无连续失败且不处于暂停；`github_search` 项目发现查询不能整体确认为可信来源。确认仅改变生命周期，不提升等级、不授予官方身份。为确认动作补充影响说明与取消路径。
- 现有更新接口不支持通用的来源重命名、改地址、改适配器、删除来源或批量提级；不要凭空画这些操作。

### 3.2 添加订阅

表单字段应来自真实契约，复杂类型说明按需展开：

| 字段 | 约束与说明 |
| --- | --- |
| 来源名称 | 必填，最多 120 字符 |
| 订阅地址 | 公开 HTTPS，最多 2048 字节；不含用户名、密码或私有 token；不是任意网页抓取入口 |
| 适配器 | RSS、Atom、GitHub Release Atom、Podcast RSS、arXiv Atom、Hugging Face 公开模型 API、GitHub 仓库元数据 API、GitHub 项目发现、Anthropic News / Research / Engineering 三种官方索引、X 登记原帖预览 |
| 内容类型 | 博客 / 文章、版本发布、播客、论文、模型元数据、仓库 / 发现候选；默认随适配器匹配 |
| 采集间隔 | `15–1440` 分钟整数；普通新增默认 60，X 默认 1440；实际调度还受适配器最低间隔和上游退避限制 |
| 主题 | 可选，最多 80 字符 |
| 等级与状态 | 当前 UI 新增固定 T2、观察中；不要新增“自动认证为官方 / T1”控件 |

添加成功后提示“来源已登记，刷新后开始采集”，不要把成功登记当作已取得文章。保留输入错误、适配器地址不匹配、保存失败仍保留表单、重复提交受控、取消未提交表单等状态。未核实的 Feed / API 不能显示虚假的绿色测试通过。

**X 是独立的有限预览流程：**

- 主页仅作身份识别，形如 `https://x.com/账号`，不含额外路径或参数；内容类型在存储上固定为 `blog`，UI 应说明是“帖子预览”，不是博客采集。
- 手动登记同一账号的 `1–20` 条原帖链接，每行一条，形如 `https://x.com/账号/status/数字`；单条最多 2048 字节，不接受其他域名、端口、片段或不支持的参数。支持的跟踪参数会规范化，不代表接受任意链接。
- 既有来源可展开登记列表，读取、编辑、保存、重试失败；保存后需要明确刷新来源才能读取新增登记项。
- 它只读取已登记公开原帖的有限预览，不自动发现主页新帖，不包含完整时间线、完整线程或全部评论。X 覆盖即使已有来源也仍是“部分覆盖”，不得改成“已完整接入”。

### 3.3 手动采集、健康与覆盖

- 区分“刷新页面上的已有数据”和“请求实际采集”。后者可能让新材料进入摘要队列并消耗已开启自动摘要的模型用量；不是无成本的列表排序操作。
- 全部刷新与单源刷新需要执行中、成功、部分成功、全部失败、没有可刷新来源、没有新内容、请求失败等状态。结果使用实际 `attempted / succeeded / failed / ingested / updated`，不能编造实时逐源百分比或进度日志。
- 部分失败时保留已成功入库内容，展示可定位的来源错误；无新增不把旧新闻发布时间改成今天。采集成功不等于摘要已经完成，也不覆盖历史晨报。
- 无取消接口时，不提供假的“终止采集”。离开页面或关闭提示不等于取消服务器任务；再次提交与未知结果要谨慎说明。
- 覆盖视图区分“已覆盖 / 部分覆盖 / 待配置或授权”，显示服务端说明与实际登记数，不承诺全网完整度。GitHub 项目发现不是官方 Trending，star 或排名不是事实可信度。
- Reddit 公开原站 Feed 的接入，不等于已获取全部帖子或评论，更不等于官方公告。X / Reddit 等返回访问限制、授权问题或限流时要保留真实错误 / 退避状态，不能暗示刷新会绕过权限或转用镜像。
- 官网页面或官网 RSS 不等于公众号自动监听；博客 / 节目 RSS 不等于作者全部社交和视频内容。领域覆盖为空或读取失败时，不推断为已经接入。
- 演示模式禁止真实来源修改与刷新；运行模式仍在确认或读取失败时，写操作先不可用并说明原因，而不是一闪而过地可点击。

### 3.4 关注名单

- 这是**关注意向及接入状态的只读名单**，不是社交平台的关注操作面板。可搜索、按平台及状态筛选、打开公开主页 / 原始文档入口、跳到关联订阅。
- 平台包括 X、微信公众号、播客 / 频道、博客、YouTube、微博、Reddit、B站、资料目录、GitHub 资料、平台关注意向。不要把某个账号或目录条目复制成示例中的真实使用者信息。
- 有关联订阅时按真实状态展示：待首次采集、已采集、已暂停、采集失败、关联订阅状态尚未读取。列表读取成功而关联来源失败时，不默认显示已接入。
- 未接入项区分：待合规授权、待适配器、待原始订阅、限流待复核、账号 / 链接待确认、未指定具体账号、仅资料参考。仅关联官网 RSS 的项仍须说明平台本身未接入。
- 关注名单不授予 T1 / T2 等级；资料目录不作为新闻来源。当前没有名单新增 / 删除 / 编辑的 UI 和写接口，不设计一键关注、平台登录或自动接入承诺。

## 4. 两套兴趣：必须分别设计，不可只补一个装饰性弹窗

### 4.1 站主“我的兴趣”：数据库偏好

## 5. 分享：本地草稿库与素材导出，不是自动发帖

### 5.1 入口、数据与边界

- 文章、晨间简报 / 当前精选、每周回顾的“制作分享卡片”创建本地草稿后进入工作台；创建中不可重复提交，失败不能导航到空白假草稿。
- 草稿保存于本地阅读库数据库，不是浏览器临时 `useState`，也不是对所有公开访客开放的云端分享空间。真实草稿功能需要持久化数据库。
- 分享只接受带原始发布者证据和可公开 HTTPS 原始链接的内容；不把聚合转载包装成原创证据。没有可分享文章、原始链接不合格、材料不存在时需要清晰阻断。
- 当前精选 / 周报可按已显示选文创建，最多 30 篇；提交内容版本与摘要时间，变更或被隐藏时会冲突。设计“内容已更新，请更新页面后重新制作”，不能自动把另一版内容替进去后仍称“与所见一致”。
- 无 AI 摘要的材料只提供原文阅读提示，不伪造 AI 摘要或全文。系统生成文档只携带标题、摘要 / 提示、来源日期、署名和原文链接等，不夹带账户、收藏、反馈、个人推荐分。

### 5.2 本地草稿库

- 展示最近 **50 份未发布且未撤销的本地草稿**，类型为文章 / 简报 / 周报、日期、标题、新草稿 / 已保存排版、继续编辑入口。50 是现有查询上限，不是当天总数或全部历史。
- 需要加载、读取失败 / 重试、空库引导、返回阅读选文和继续编辑状态。不要补出没有能力支撑的无限历史分页、云同步、协作权限、批量发布或完整资产管理。
- 当前列表没有删除、复制、标签或分享统计动作；不为装饰性完整感伪造这些功能。

### 5.3 编辑工作台

保留“封面 / 选文 / 文案”三个任务步骤与即时卡片预览，视觉遵循已确认的 NewsScout 编辑风格，不另造营销品牌。

| 内容 | 真实编辑约束 |
| --- | --- |
| 封面标题 | 必填，最多 120 字符 |
| 副标题 | 最多 120 字符 |
| 尾页引导语 | 最多 100 字符 |
| 选文标题 / 卡片正文 | 标题必填、最多 200 字符；正文最多 4000 字符 |
| 发帖文案 | 最多 12000 字符；这是本工具编辑上限，不是小红书平台字数承诺 |

- 默认选前五篇，是可修改的素材默认选择，不是阅读进度。支持逐篇选择 / 取消、改标题和正文；预览 / 导出至少需一篇。草稿全未选时可以保留编辑状态，但不能生成有效卡片。
- 不增加任意导入文章、拖拽改变原始条目索引或删除原始出处的结构化编辑器；后端校验草稿条目与原始文档按索引一一对应。
- 原始署名、来源日期与链接可核验；来源未提供日期时如实标注。长正文自动续页而非无限缩小文字；标题过长、封面放不下、渲染分页过多时给出可修正原因。

- 本轮默认原型不增加“复制公网链接”“生成二维码”“一键发布”。若需要说明，将其作为“已有条件式后端、缺少产品 UI / 部署前提”的后续项单列，不能因网站本身可公网访问就假定分享站点已配置。
