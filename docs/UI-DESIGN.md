# UI 设计与独立评审

适用版本：0.2；维护日期：2026-09-17。重点是可阅读、可返回、可解释的界面，不是替换组件库。源码集中在 `apps\web\src`；组件文件位于其 `components` 子目录。

## 1. 设计目标与组件选择

读者首先应能扫描新闻、选择文章、理解要点与真实来源，再处理收藏等辅助操作。管理、采集和模型账户不应占据阅读页面主层级。

保留 Fluent UI 基础控件及其组合/键盘行为；阅读组合组件由项目直接维护。借鉴代码自有、API 一致的设计方式，但**没有引入 shadcn/ui、Tailwind、Radix 或 CVA**。换库不能代替实际截图和交互评审。

| 设计项 | 当前规范 |
| --- | --- |
| 配色 | Clawpilot `--cp-*` 变量；明暗主题共享语义，不在组件里另造色板 |
| 字体 | Segoe UI 优先，沿用项目中文 fallback；代码文字使用等宽字体 |
| 圆角 | 控件 10px，文章卡片 16px |
| 间距 | 以 4px 为基础节奏，统一密度；不靠额外空卡片制造“层次” |
| 操作层级 | 主、次、轻量、危险操作由 `ReaderButton` 统一；收藏和阅读价值不与标题争抢注意力 |
| 可追溯性 | 原题、来源、实际日期和来源内容范围不可因“美化”被删除或改写 |

## 2. 共用组件契约

| 组件 / 样式 | 维护职责 |
| --- | --- |
| `ReaderShell`、`ReaderNavigation` / `styles.ts`、`reader-navigation.css`、`editorial-reader.css` | 页面宽度、导航断点、当前入口、个人/公开差异 |

| `ReaderControls` / `reader-controls.css` | 按钮、页签、输入/选择器焦点、错误和起始状态 |
| `RadarControls`、`RadarFilterChips` | 三视图、主筛选、渐进高级筛选、清除条件 |
| `TopicWorkspace` / `topic-explorer.css` | 图谱/结果/文章切换，真实样本量与选中主题 |
| `SummaryContent`、`ReadingValue` / `summary-content.css`、`editorial-reader.css` | 紧凑/完整要点、阅读价值与诚实的材料呈现 |
| `PublicArticlePane`、`EventPreviewPane`、`useReaderDialog` | 详情内容、操作注入、窄屏焦点约束与返回 |

`public-reader.css` 只负责公开页的特定组合，不重新实现一套公共阅读组件。公开数据不能为了复用而伪装成带有个人状态的完整 `Event`。

## 3. 文字宽度与预览

卡片标题使用可用宽度，正文跟随实际内容列，不再统一固定为 760px。`ReaderStory` 使用 Grid：

- 卡片内容容器达到 1000px 时，真实辅助操作列为 160px，加 24px 列间距离；这是**容器宽度**，不是整个浏览器窗口断点。
- 标题仍横跨可用宽度。操作区位于标题下方，不能与长标题重叠。
- 阅读价值打开、保存中或出错时，操作区回到完整宽度的下方，卡片高度随之增长；不能覆盖下一条新闻。
- 没有操作的分组卡片不保留空的侧栏。窄屏不为侧边按钮挤压文字。
- 展开的阅读价值使用所在内容列的完整宽度，不再限制为 75ch；长单词/链接应安全换行。

**宽度、字符预算和行数是三件事。** `compactSummaryPoints` 最多取前两点并共享 240 字符预算；非 Copilot 紧凑摘录也有 240 字符预算。晨报和公开摘要预览还应用两行显示限制；紧凑行保持单行省略。打开文章才显示完整要点，不为填满宽卡片新增或重跑摘要。

调整时应测量正文实际宽度、空白与操作区位置，并使用足够长的真实/受控文本。仅证明 `scrollWidth <= innerWidth`，不能证明文字没有过早换行。长篇阅读区与列表预览可以有不同的行长策略，不能一律去掉所有阅读约束。

## 4. 焦点的归属

Fluent Select/Input 由组件自己的 `focus-within` 指示器提供焦点反馈，公开页的通用 outline 规则排除其原生子控件。Select 的底线固定为 2px，不能因为共用的 10px 圆角而变成 5px 色带。

普通标题、按钮、链接和 disclosure summary 仍有键盘焦点；不得全局使用 `outline: none`。选择器/输入框在鼠标点击后也可能匹配原生 `:focus-visible`，不能把这个选择器直接当作“仅键盘”证明。

规则调整还要保留特异性：目前通过 `:not(:where(...))` 排除 Fluent 子控件，避免新的选择器权重盖过标题已有的 4px outline offset。验证鼠标、Tab/Shift+Tab、方向键实际选择、明暗主题及 forced-colors，不仅比较一张点击截图。

## 5. 响应式与阅读上下文

| 条件 | 预期 |
| --- | --- |
| 窗口宽度至少 1200px | 完整侧栏 |
| 861–1199px | 72px 导航栏，内容仍有可用空间 |
| 不超过 860px | 固定五个底部阅读入口，主要按钮和选择器至少 44px |
| 不超过 560px | 卡片内边距 16px、标题 18px；操作区按需换行 |
| 常规文章阅读不超过 980px | 聚焦文章，保留关闭、位置与前后篇；背景导航不能盖住阅读窗口 |
| T1 深读至少 1280px | 312px 队列与阅读区并排；较窄宽度聚焦文章 |
| 主题工作区窄屏 | 地图/结果切换，主动选文后聚焦文章；关闭后恢复结果上下文 |

移动主题阅读不能被父级 stacking context 隔离到固定底部导航之下；`reader-extras.css` 中活动对话框解除隔离的规则具有行为意义，不是可随意删除的装饰。

返回应恢复打开者、选中主题/分组、列表位置和独立滚动区域。父控制器与子工作区不能互相抢焦点；无限分页后的个人状态更新必须覆盖已载入的所有页。

访客兴趣使用 `PageHeader.action`，不新增第六个底部入口。受控 Fluent Dialog 中标题与关闭按钮同排；主题区独立滚动，取消/保存始终可达。窄屏单列，桌面双列，选择后才显示关注程度。Escape 只关闭兴趣编辑，恢复入口焦点，不顺带关闭背后的文章。

对话框的关闭目标至少 44×44px。复选框应对齐实际图形、文字及关注程度，不仅让外层高度相等；图形在触摸高度内居中。按钮保留共用外轮廓，移除 Fluent 聚焦态额外的 inset 阴影，避免双重焦点；这个覆盖仅限兴趣对话框，正常主题与 forced-colors 都保留可见反馈。

勾选是草稿，保存成功才应用；清空选择仍需保存，损坏记录的重置有二次确认。失败时把滚动内容定位到错误提示，保留草稿及页脚操作。跨页面更新只提示，不自动重排本页或丢弃打开的草稿。说明必须区分“浏览器保存”和“推荐读取请求会携带主题”，不能声称兴趣从不发送。

## 6. 文案与状态

| 场景 | 应表达 | 不应表达 |
| --- | --- | --- |
| 展开文章 | 阅读要点与来源内容 | 未取得全文却写“打开原文阅读” |
| 阅读价值 | 现有摘要对内容价值的简明解读；没有则不编造 | `article-value-v1`、基础值、类型和加分日志 |
| T1 技术识别 | 实际分类/栏目/规则依据，明确不等于质量认证 | 技术标题命中即“已验证深度技术” |
| 加载 | 对应布局骨架，保持已知标题；可关闭或切换详情 | 还没返回数据就显示“0 篇” |
| 空结果 | 当前条件下无材料，并保留可调整的条件 | 把接口失败显示成无新闻 |
| 失败 | 明确错误与一次可执行重试；保留阅读上下文 | 无限重试、静默旧缓存或成功样式 |
| 开始深读 | 未选文章时友好的起始提示与可用队列 | 空白巨型详情框或自动打开第一篇 |
| 晨报分享 | 整版/详情中的个人分享入口 | 每个晨报条目重复展示分享卡片 |
| 来源管理 | 来源状态和用户可理解的说明 | 把目录导入出处等审计文字铺满普通列表 |

主动收藏/不感兴趣应有保存中、失败、撤销反馈；公开版的反馈仅属于当前浏览器。危及数据的管理操作需确认和取消路径，但不得为了截图在站主日常数据库上试验。

## 7. 独立 UI Critic 如何运行

角色定义在 `.github\agents\ui-critic.agent.md`，名称为 `newsscout-ui-critic`。它是**只读的独立评审角色**，不是运行中的服务，也不是设计师人工批准或无障碍认证。

`scripts\capture-ui-review.cjs` 和 `npm run ui:review` 只负责收集浏览器截图/指标，不调用 AI、不输出自动评分、不修改代码。Coding Agent 或维护者显式启动独立评审，之后负责修正并请同一评审者复查。

1. 明确本次变更范围、受影响入口和个人/公开差异，保存同尺寸、同内容的前后对照。
2. 构建候选，按 [测试指南](TESTING.md) 取得交互证据；截图目标必须是声明只读的公开网关。
3. 把目录、manifest、变更范围和行为证据交给独立 Critic；没有看过的范围标为未评审。
4. 按 P0/P1/P2 修正具体问题，并按同一 ID 复查；不能把测试通过当视觉通过。
5. 发布后再看真实 HTTPS 入口，确认仍是被评审的构建；保留记录而不覆盖旧目录。

```powershell
# 综合：阅读入口、Radar 三视图、主题阅读、代表性详情与恢复状态
npm.cmd run ui:review -- --base-url http://127.0.0.1:5190 --output tmp\ui-reviews\my-full-review

# 专项：1440 / 1920 / 390，明暗主题、展开阅读价值、鼠标/键盘选择器焦点
npm.cmd run ui:review -- --base-url http://127.0.0.1:5190 --scope width-focus --output tmp\ui-reviews\my-width-review

# 专项：兴趣入口、编辑/滚动、真实推荐与主题结果、模拟存储失败
npm.cmd run ui:review -- --base-url http://127.0.0.1:5190 --scope interests --output tmp\ui-reviews\my-interest-review
```

实际运行必须改用新的命名目录；可用 15190 候选网关替换目标地址。综合采集覆盖 1280/1024/768/390 和代表性深色状态；2560px 长内容、个人版相同内容、pending/error、forced-colors 等由对应定向 UI 用例补充，不谎称一个 capture 命令覆盖全部。

`review.json` 包含视口、实际正文/操作/阅读价值宽度、焦点轮廓和底线、三视图状态、告警、脚本错误和被拦截请求。`safe=true` 只说明这次采集未记录页面错误或禁止请求，**不是视觉验收通过**。浏览器模拟的加载/失败/空状态有 `simulated` 标记，不改服务器内容。

兴趣专项在新的浏览器环境中使用明确的审阅偏好，不读取维护者浏览器记录；覆盖 1280/1024/768/390 及代表性深色状态，记录对话框/页脚/复选框位置和真实兴趣 GET 返回。390px 另采集明暗下的真实指针按下及 forced-colors 焦点。存储配额失败单独标记为模拟，并检查错误实际在内容视口中，不为截图人为补滚动。真实语料截图不能代替分组前排序、跨浏览器/跨页、草稿冲突和历史不变量的定向测试。

## 8. 可直接交给评审者的说明

```text
范围：列出改动和未改动的页面/行为。
证据：前后截图目录、review.json、个人/公开同内容截图、相关交互结果。
约束：只读，不改代码/数据/部署，不访问站主管理 API。
请检查：层级、密度、真实正文宽度、对齐、操作区重叠、焦点、明暗和中间尺寸。
涉及两端时逐项比较：视图、筛选、排序、分页、主题选择、详情及返回。
输出：Needs changes 或 Ready for visual acceptance；列出具体 ID、优先级、
页面/尺寸、文件证据、用户影响和建议。缺失证据写未评审，不扩大结论。
复查：逐项标为已修复、部分修复、未解决或未验证，并说明新回归。
```

P0 是主任务阻断/误导/不可访问；P1 是实质层级、可读性、导航或交互问题；P2 是有限影响的打磨。评审意见要有实际证据，不为了凑数量复制通用建议。已有非阻塞 P2-RP-01 见 [项目状态](PROJECT-STATUS.md)。
